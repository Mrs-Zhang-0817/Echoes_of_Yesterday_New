# 《昨日重现》UI Design System

> 项目：Echoes of Yesterday /《昨日重现》  
> 文档性质：视觉、交互与 UI 构建规范  
> 适用对象：游戏开发、UI/UX 设计、美术、技术美术、测试  
> 基准画布：1280 × 720，16:9，优先适配横屏 HTML5 与抖音互动空间  
> 规范状态：基于当前项目已实现系统整理，作为后续 UI 的统一设计基线

---

## 1. 设计总纲

### 1.1 核心定位

《昨日重现》的 UI 不是覆盖在游戏画面之上的普通 HUD，也不是现代网页、移动应用或任务系统的换肤版本。

UI 本身就是叙事空间的一部分：玩家不是在操作菜单，而是在陪伴一位老人重新翻阅、整理和辨认自己的人生档案。页面、照片、纸片、印章、笔迹和磨损共同承担叙事。

核心设计命题：

> 老人记忆中的旧档案、手写记录与逐渐恢复的人生碎片。

核心关键词：

- 旧照片
- 泛黄纸张
- 手写记录
- 家庭档案
- 记忆恢复
- 时间痕迹
- 人情温度
- 克制、安静、缓慢

### 1.2 玩家心理感受

UI 应让玩家感到：

- 自己正在触碰真实保存多年的物件，而非点击抽象控件；
- 信息不是被系统“发放”，而是从模糊记忆中逐渐浮现；
- 每次恢复都带有珍惜、迟疑和温度，而非奖励结算的兴奋感；
- 档案虽然陈旧，却被认真保存，呈现温暖而非恐怖、腐败或脏乱；
- 页面有足够停顿和呼吸，让玩家愿意阅读并凝视照片。

### 1.3 设计判断原则

任何新增 UI 在评审前应回答三个问题：

1. 它看起来像一件属于这个家庭档案的实体物件吗？
2. 它的出现与反馈是否像翻阅、触碰、发现或回忆，而非网页响应？
3. 去除背景后，它是否仍与项目的纸张、墨迹、照片和时间感一致？

若任一答案为“否”，应重新设计，而不是增加更多装饰进行掩盖。

## 2. 视觉语言

### 2.1 色彩体系

整体色彩必须保持暖、旧、低饱和。色彩用于表达纸张年代、墨迹深浅、记忆清晰度和归档状态，不用于制造现代 UI 的强对比刺激。

#### 核心色

| 角色 | 当前基准值 | 使用说明 |
|---|---:|---|
| 页面外背景 | `#2A1B12` | 深暖褐色，承托档案页面，不抢夺内容 |
| 主标题墨色 | `#4A2E1B` | 最深的手写/标题墨迹 |
| 章节墨色 | `#5A3822` | 章节标签、次级标题 |
| 正文墨色 | `#6B5744` | 描述、记忆条目、说明文字 |
| 手写墨色 | `#686056` | 情绪文字、私人笔记，略灰、较柔和 |
| 控件墨色 | `#5A3A20` | 按钮与交互标签 |
| 系统小字 | `#3A2415` | 日期、英文副标题、刻度等小型信息 |

#### 纸张色范围

纸张不使用单一纯色，应在以下暖色范围内通过真实纹理和轻微叠色形成层次：

- 浅旧纸：`#F1DDAE` 附近
- 中间纸张：`#DFC18A` 附近
- 深度纸边：`#B9894F` 附近
- 氧化阴影：暖棕或深褐，不使用中性纯黑

#### 辅助色

| 角色 | 建议范围 | 使用说明 |
|---|---|---|
| 印章红 | 暗砖红、褪色朱红 | 归档、日期、重要确认；禁止鲜红 |
| 草木绿 | 灰橄榄绿、旧军绿 | 已恢复、完成标记、植物装饰 |
| 暗金色 | 黄褐、旧铜金 | 记忆被唤醒时的轻微暖色强调 |
| 未恢复灰 | 暖灰、灰褐 | 未知内容、不可用信息、遗忘状态 |

#### 禁止色彩

- 高饱和蓝、紫、青和荧光色；
- 霓虹光、赛博科技色、RGB 分离效果；
- 大面积纯白或纯黑；
- 现代手游常见的奖励金、品质紫、警告红；
- 用鲜艳颜色代替信息层级。

### 2.2 材质语言

所有主要 UI 表面应具有实体材料依据。优先级如下：

1. 完整美术资产；
2. 真实纸张、照片、胶带、印章纹理的组合；
3. 轻量 CSS 材质增强；
4. 纯 CSS 绘制仅用于简单动态层和占位，不承担复杂最终视觉。

纸张应包含：

- 可辨识但不过强的纤维或颗粒；
- 泛黄和局部氧化；
- 不规则、磨损或手工裁剪边缘；
- 纸层之间轻微暖色阴影；
- 不同纸片之间细微色差、旋转与厚度差；
- 胶带、折痕、压痕或存放痕迹，但不得堆满装饰。

照片应包含：

- 轻微褪色、棕褐化、低饱和；
- 旧照片相纸或纸质边框；
- 与记忆清晰度相关的灰度、模糊、亮度和饱和度变化；
- 合理的压放、粘贴或夹入关系。

禁止：

- 毛玻璃、亚克力、镜面高光；
- 无材质依据的扁平卡片；
- 现代圆角卡片矩阵；
- 默认浏览器边框和阴影；
- 过度脏污、重颗粒导致信息不可读；
- 所有纸片完全相同的纹理和边缘。

### 2.3 阴影与层次

阴影用于说明纸张厚度与叠放关系，不用于制造悬浮面板。

- 阴影颜色使用暖深褐，如 `rgba(48, 28, 14, .15–.30)`；
- 背景纸层阴影最浅，内容纸片居中，照片和便签可更深；
- 常态阴影应柔和、方向统一；
- hover 只允许轻微增加阴影距离或浓度；
- 禁止黑色硬阴影、彩色外发光和大范围悬浮光圈。

当前纸张深度语义：

| 深度 | 用途 |
|---|---|
| `background` | 档案底页、最下层纸张 |
| `middle` | 次级纸层、分区衬纸 |
| `content` | 主要信息纸片 |
| `sticky` | 便签、标签、临时记录 |
| `photo` | 照片与相框，视觉层级最高之一 |

## 3. 字体与墨迹系统

### 3.1 字体角色

项目字体按角色管理，不允许页面自行指定任意字体。正式资源保持以下文件接口：

- `Title.ttf`
- `Chapter.ttf`
- `Body.ttf`
- `Handwriting.ttf`

当前字体族接口：

- `YesterdayTitle`
- `YesterdayChapter`
- `YesterdayBody`
- `YesterdayHandwriting`
- `YesterdaySystem`

自定义字体未就绪时仅允许使用既定楷体、仿宋、宋体回退链。不得以现代黑体作为主要视觉字体。

### 3.2 标题字体

用途：

- 页面主标题；
- 章节大标题；
- 重要档案标题。

特征：

- 有手写或旧式记录感；
- 笔画有力度，但不追求完美几何边缘；
- 比正文墨色深，像反复书写或标题笔迹；
- 有年代感，但不能过度书法化到难以阅读。

当前基准：

- 主标题字号：`clamp(38px, 5vw, 64px)`
- 主标题颜色：`#4A2E1B`
- 字距：`-0.02em`
- 不透明度：约 `.96`
- 章节标题字号：`clamp(26px, 3vw, 38px)`
- 章节标题颜色：`#5A3822`
- 字距：约 `.04em`

禁止：

- 默认黑体、商业网页无衬线字体；
- 现代品牌标题字；
- 过细、过锐或装饰性过强的书法字；
- 明显描边、浮雕和发光文字。

### 3.3 正文字体

用途：

- 剧情与档案描述；
- 已恢复/未恢复记忆；
- 提示内容；
- 进度说明。

要求：

- 第一优先级是可读性；
- 具有仿宋或旧笔记感；
- 笔画细腻、低调，不与标题竞争；
- 长文本保持舒展行距。

当前基准：

- 字号：`clamp(18px, 1.8vw, 24px)`，组件内可按空间缩小；
- 颜色：`#6B5744`
- 字距：约 `.025em`
- 行高：推荐 `1.5–1.7`
- 不透明度：约 `.91`

### 3.4 手写情绪文字

用途：

- “心里的话”；
- 私人回忆；
- 照片背面式注释；
- 带感情色彩的短句。

特征：

- 比正文更松弛、更私人；
- 墨色偏灰，像多年后留下的铅笔或淡墨；
- 可使用轻微倾斜和不均匀墨迹，但不能牺牲阅读。

当前基准：

- 字号：`clamp(20px, 2vw, 28px)`
- 颜色：`#686056`
- 字距：约 `.035em`
- 行高：约 `1.35–1.5`
- 不透明度：约 `.88`

### 3.5 数字、日期与刻度

用于日期、百分比和记忆清晰度的数字必须与档案语境一致：

- 使用正文、章节或既定系统字体角色；
- 百分比可轻微斜体，模拟手写记录；
- 日期可使用印章式排列和轻微旋转；
- 刻度字应小、克制、低对比；
- 禁止七段数码管、科技 HUD 数字、等宽终端字体。

### 3.6 墨迹质感

字体不是“换一个字体文件”即可完成。最终文字应同时处理：

- 暖褐色而非纯黑；
- 角色化字号、字距和行距；
- 轻微不透明度差异；
- 亚像素级暖色阴影，模拟墨水吸收与边缘扩散；
- 极轻的对比度和饱和度修正；
- 在支持的浏览器中使用低强度遮罩模拟局部缺墨。

当前文字纹理通过 `.typography-texture-enabled` 总开关启用。该效果必须保持可关闭，以支持性能测试和视觉对照。

文字质感禁止：

- 明显模糊；
- 可见的重复噪点图案；
- 黑色描边；
- 发光或现代投影；
- 每个字大幅随机旋转；
- 使用实时 Canvas 逐字运算作为常规方案。

### 3.7 字体加载规范

依赖自定义字体的页面不得先显示系统字体再切换。

标准流程：

1. 页面文本容器初始隐藏；
2. 通过 `FontManager` 加载字体；
3. 等待 `document.fonts.ready`；
4. 添加 `font-ready`；
5. 内容以约 400ms 的低调淡入显示；
6. 后续页面或记忆动画才允许开始。

字体加载失败时应使用既定回退链安全显示，不得让页面永久空白。

## 4. 页面布局系统

### 4.1 基准与适配

- 基准画布：1280 × 720；
- 基准比例：16:9；
- 页面容器保持完整比例，横屏居中；
- 使用百分比坐标、`clamp()` 与相对尺寸；
- 不因不同窗口尺寸重新排成现代响应式 Dashboard；
- 安全区域外使用深暖褐背景承托；
- 触屏环境需保留足够点击面积，视觉资产可小于交互区域。

### 4.2 图层规范

当前统一图层顺序：

| Level | 图层 | 内容 |
|---:|---|---|
| 0 | Background | 固定背景、整页美术底图 |
| 1 | Paper Frame | 档案页、纸框、底层结构 |
| 2 | Static Decoration | 胶带、植物、印章、静态装饰 |
| 3 | Dynamic Content | 照片、进度、列表、可变内容 |
| 4 | Text | 标题和需要独立控制的文字 |
| 5 | Interaction | 按钮、热点、可操作覆盖层 |

非交互图层默认不接收指针事件。交互层必须拥有清晰的语义和可访问名称。

### 4.3 Memory Report 布局

Memory Report 是本设计系统的核心页面模板：

- 顶部：章节归档信息、页面主标题、英文副标题、日期印章；
- 左上：章节照片，像夹在档案中的实体相片；
- 左侧：本章总结、记忆清晰度、情绪文字；
- 中央：已恢复记忆列表与归档标记；
- 右侧：尚未想起的记忆；
- 底部：继续、档案、主页三个纸片式功能按钮。

当前内容区域采用非对称三栏，而不是等宽网格。照片、纸片和装饰允许轻微偏移和旋转，以保持手工档案感。

### 4.4 留白与信息密度

- 每个纸片只承担一个明确的信息主题；
- 标题与正文之间保留可见呼吸空间；
- 列表条目宁可减少数量，也不压缩到拥挤；
- 装饰不得填满所有空白；
- 纸张叠放应形成视觉路径，而不是规则卡片阵列；
- 未恢复区域应显得安静、留白、等待，而非“未解锁任务列表”。

禁止：

- 现代后台式 Dashboard；
- 等宽卡片网格；
- 密集工具栏；
- 过多徽标、数字角标和状态标签；
- 以分割线填满所有区域。

## 5. 按钮系统

### 5.1 按钮本质

按钮应像贴在档案里的纸片、标签或独立美术贴片，而不是网页按钮。

复杂按钮视觉优先由美术资产提供。代码负责：

- 加载图片；
- 配置位置和点击区域；
- 管理状态；
- 应用轻量 transform、filter、opacity；
- 触发导航、声音和事件。

不得在完整美术按钮之上再次生成文字、边框、纸张背景或图标。

### 5.2 唯一状态模型

所有按钮统一使用以下状态：

| 状态 | 语义 | 视觉 |
|---|---|---|
| `default` | 可操作、静止 | 旧纸、低饱和、稳定阴影 |
| `hover` | 记忆被轻微唤醒 | 上浮、略亮、墨色增强 |
| `pressed` | 正在触碰纸片 | 轻微回缩或下压 |
| `disabled` | 暂不可操作 | 降低透明度和饱和度，禁止 hover |
| `completed` | 已完成或已归档 | 稳定纸张、小型旧印章或灰绿标记 |

状态必须由统一 `Button` 逻辑管理。页面不得直接修改按钮 CSS 类来模拟状态。

### 5.3 Default

- 泛黄旧纸或完整按钮图片；
- 暖棕墨色；
- 轻微纸纹与磨损边缘；
- 阴影微弱且贴近纸面；
- 不使用 CSS 默认 border；
- Artwork 页面中的按钮资产在页面出现时立即完整显示，不播放入口淡入。

### 5.4 Hover

标准持续时间：300–500ms；当前基准为 400ms。

标准变化：

- `translateY(-2px)`；
- 普通纸片保持 `scale(1)`，独立图片贴片可使用 `scale(1.03)`；
- `brightness` 轻微提高至约 `1.08–1.10`；
- `saturate` 轻微恢复至约 `1.03`；
- 暖黄色光晕只能作为极轻辅助；
- 墨色增强，但不得锐化成数字 UI。

Hover 的情绪是“记忆被唤醒”，不是按钮跳出来邀请点击。

禁止：

- 弹跳；
- 大幅缩放；
- 强烈外发光；
- 快速闪白；
- 无限循环呼吸；
- 移动布局或挤压相邻元素。

### 5.5 Pressed

标准持续时间：100–150ms；当前基准为 130ms。

- HTML 纸片按钮可轻微下压；
- 图片贴片按钮使用约 `scale(.98)`；
- 阴影收缩、亮度略降；
- 触发 `button:paper-sound-request` 声音接口；
- 不使用弹簧回弹。

### 5.6 Disabled

- 降低透明度，当前常用约 `.52–.55`；
- 降低饱和度和亮度；
- 禁止 hover、点击和键盘激活；
- 光标显示不可操作；
- 动画锁定期间仍须遵循页面特例：若按钮在视觉上应一直贴在档案上，只锁交互，不应制造入口淡入。

### 5.7 Completed

- 保持纸张稳定，不继续吸引注意；
- 使用灰绿、褐绿完成标记；
- 可附加小型“已归档”印章；
- 禁止亮绿色对勾、金币粒子和庆祝光效。

### 5.8 交互与可访问性

- 每个按钮必须有稳定 ID 与 `aria-label`；
- 支持鼠标、触屏、Enter 和 Space；
- disabled 同步设置 `aria-disabled`、点击能力和焦点顺序；
- 交互热点可以略大于不规则视觉边缘；
- 状态变化通过 `data-button-state` 表达；
- 新页面复用现有 `Button`，不得创建第二套按钮状态机。

## 6. 提示框与弹窗

本节为后续扩展的强制规范。

### 6.1 视觉类型

| 类型 | 推荐物件隐喻 |
|---|---|
| 剧情提示 | 写在纸条或照片背面的短句 |
| 交互提示 | 临时便签、铅笔标记、折角标签 |
| 确认弹窗 | 单独抽出的档案纸或信笺 |
| 错误提示 | 退回标记、批注、褪色红章 |
| 任务提示 | 档案索引条或待整理纸条 |

### 6.2 构建规则

- 使用纸张、胶带、折角、手写批注、印章等实体语言；
- 主体与遮罩均使用暖色，不使用纯黑半透明遮罩；
- 标题简短，正文克制；
- 主次操作都沿用统一 Button；
- 错误状态仍保持温和，不以鲜红闪烁惊吓玩家；
- 弹窗层级应像“从档案中抽出一张纸”，而非悬浮应用窗口。

### 6.3 动画

推荐：

- 轻微展开；
- 小幅 `translateY`；
- 极轻的角度校正；
- 纸张从叠层中抽出；
- 360–620ms 的自然出现。

禁止：

- 从中心大幅 scale；
- 商城礼包式弹出；
- 橡皮筋、果冻和弹簧动画；
- 霓虹描边、强光扫过；
- 连续抖动和闪烁。

## 7. 动画与动效

### 7.1 核心原则

动效关键词：

- 慢；
- 自然；
- 有呼吸；
- 有物理依据；
- 服务阅读；
- 服务记忆恢复叙事。

动画不应证明“系统响应很快”，而应表达纸张、照片、墨迹和记忆正在发生变化。

### 7.2 时间尺度

| 类型 | 推荐时长 | 当前基准 |
|---|---:|---:|
| 按压反馈 | 100–150ms | 130ms |
| Hover | 300–500ms | 400ms |
| 小型照片/文字显现 | 300–800ms | 300–800ms |
| 印章动作 | 700–1600ms | 720–1600ms |
| 页面翻页/切换 | 800–1200ms | 900–1000ms |
| 照片清晰度恢复 | 1–2s | 约 1200–2000ms |
| 完整记忆恢复演出 | 按叙事需要 | 长于普通 UI，分阶段执行 |

### 7.3 缓动

推荐缓动：

- 纸张与按钮：`cubic-bezier(.22, .7, .25, 1)`；
- 页面翻动：`cubic-bezier(.38, .05, .16, 1)`；
- 墨迹、亮度和透明度：柔和 `ease-out` 或 `ease-in-out`。

避免：

- `linear` 用于明显位移；
- 弹簧、回弹和 overshoot；
- 多个元素无意义地按网页列表逐条飞入。

### 7.4 记忆恢复动效

记忆恢复允许比普通 UI 更长，但必须表现连续恢复过程：

- 纸张从沉寂到温暖；
- 缩略图像照片显影；
- 照片从灰、暗、模糊到较清晰；
- 文字从淡、缺失到可辨；
- 记忆清晰度数字与进度同步；
- 完成印章作为收尾；
- 情绪文字在完成阶段安静出现。

避免：

- 奖励结算；
- 粒子爆发；
- 元素机械逐个弹出；
- 为满足时长而人为切割节奏；
- 页面先显示最终状态再回退到起始状态。

### 7.5 动画与交互锁

重要演出开始时应发布 `MEMORY_RESTORE_LOCK`，锁定：

- 返回；
- 章节切换；
- 主菜单；
- 手动盖章；
- 其他可能破坏演出的操作。

结束或异常恢复时必须发布 `MEMORY_RESTORE_UNLOCK`。页面关闭或取消后不得继续执行计时器、Promise 或 DOM 动画。

### 7.6 减少动画

所有新动效必须支持 `prefers-reduced-motion: reduce`：

- 直接进入安全最终状态；
- JS 不得继续等待完整演出时长；
- 保持内容、状态和导航完整；
- 不得仅在 CSS 中缩短动画，而让业务 Promise 继续等待。

### 7.7 禁止动效

- 快速弹窗；
- 闪烁；
- 频繁摇晃；
- 页面元素大幅飞入；
- 现代游戏 HUD 扫描线；
- 无叙事意义的循环动画；
- 大量 JS 高频写 DOM；
- 同一状态同时由 CSS 与 JS 分别驱动而相互冲突。

## 8. 图片与美术资产规范

### 8.1 总体原则

复杂视觉优先美术资产驱动。代码负责布局、交互、状态、遮罩和轻量动态，不负责重新绘制完整纸张、插图或按钮。

### 8.2 背景图

- 16:9 页面底图按完整画布输出；
- 保留纸张、照片、装饰和静态排版时，应明确哪些区域仍由代码动态覆盖；
- 动态区域不得在底图中重复烘焙同样的数字、文字或进度；
- 图片以相对路径加载；
- 不依赖服务器处理、Node API 或文件系统 API。

### 8.3 按钮图片

- 可使用带透明通道的完整按钮 PNG；
- 图片包含纸张、图标和文字时，HTML 不得重复绘制；
- 透明边缘应干净，不保留白色矩形底；
- 资产必须完整遮盖底图中的旧按钮，或使用不含按钮的背景；
- 位置与裁切使用配置管理，不散落在 CSS；
- 图片层负责视觉，统一 Button 负责交互。

### 8.4 照片

- 保持原始宽高比，通常使用 `object-fit: cover` 或 `contain`；
- 老化效果应与故事年代一致；
- 低清晰度不是简单大幅模糊，应结合灰度、低饱和、低对比、暗度和纸面旧化；
- 清晰度提高应逐步恢复颜色和细节；
- 左上章节照片覆盖需预留独立接口，不直接破坏整张底图。

### 8.5 纸张与纹理

- 纹理应可平铺或覆盖，避免明显接缝；
- 纸纹强度低于文字和照片；
- 同一页面可共享纸张家族，但应有色调、边缘和旋转差异；
- 不把高频噪点作为“旧”的唯一表达；
- 运行时材质采用轻量 CSS，避免移动端持续 Canvas 运算。

### 8.6 印章与标记

- 使用褪色朱红、暗绿或棕色；
- 边缘允许缺墨和不完整；
- 印章角度小幅偏转；
- 动画包含落下、轻微回弹和墨迹扩散；
- 一次演出只创建并管理一个印章实例，避免重复盖章。

### 8.7 资源交付检查

美术交付前确认：

- 文件命名稳定、含义清晰；
- 尺寸、比例和坐标基准明确；
- PNG 透明通道真实存在；
- 无意外白边；
- 动态覆盖区域已清空或明确遮盖策略；
- 文字是否烘焙进图已标注；
- 图片压缩后无明显色带和锐化边；
- HTML5 环境可直接通过相对路径读取。

## 9. 交互设计原则

所有交互都应服从同一叙事隐喻：

> 老人正在重新翻阅自己的记忆档案。

对应关系：

| 玩家行为 | 叙事表达 |
|---|---|
| Hover | 手指靠近纸片，沉睡的记忆轻微被唤醒 |
| 点击 | 按下、掀起或确认一张纸 |
| 页面切换 | 翻页、抽出下一份档案 |
| 发现线索 | 找到旧照片、批注或被遗忘的物件 |
| 恢复记忆 | 照片显影，文字与色彩逐渐清晰 |
| 完成 | 盖章归档，安静确认 |
| 不可操作 | 纸片褪暗或暂时不可触碰 |
| 错误 | 档案批注或退回标记，而非系统警报 |

反馈必须明确，但不应吵闹。声音建议使用纸张摩擦、轻触、翻页、木桌和印章等拟物声音，不使用电子提示音。

## 10. 开发构建规范

### 10.1 新增 UI 的强制流程

1. 明确该 UI 在档案世界中的实体隐喻；
2. 检查是否可复用现有组件和材质；
3. 选择动态 HTML 组件或完整美术资产方案；
4. 使用既有字体角色、颜色与图层；
5. 使用统一 Button 和状态系统；
6. 将位置、尺寸、资源路径与动态区域配置化；
7. 接入键盘、触摸和 ARIA；
8. 接入 reduced motion；
9. 验证 16:9、移动端性能与相对路径；
10. 与旧页面对比，确认没有出现现代 UI 语言。

### 10.2 禁止事项

- 新建另一套 Button 系统；
- 页面直接操作按钮 CSS 状态；
- 使用浏览器默认按钮、输入框或边框作为正式视觉；
- 在各页面复制一套不同色值和动画参数；
- 使用 Node、文件系统或服务器 API 作为运行时依赖；
- 把复杂美术完全用 CSS 渐变勉强重画；
- 将整页所有内容烘焙进图片后又用 HTML 重复覆盖；
- 未等待字体就显示自定义字体文本；
- 忽略取消、异常和 reduced motion 生命周期；
- 重构现有 Memory 核心来解决单一页面视觉问题。

### 10.3 CSS 与动画实现

- 高频动画只使用 `transform`、`opacity` 和 `filter`；
- 状态切换使用 class 或 `data-*`，避免逐帧写内联样式；
- 时长和缓动集中为 token；
- 动态尺寸使用 CSS 自定义属性；
- 移动端避免大型实时模糊和大量 SVG/Canvas 滤镜；
- 所有可关闭的增强效果应提供根级开关。

### 10.4 运行环境

必须支持：

- 浏览器 HTML5；
- 抖音互动空间环境；
- 静态文件部署；
- 相对路径资源；
- DOM、CSS 动画、Font Loading API、`fetch()` 静态 JSON；
- `localStorage` 不可用时安全降级。

不得依赖：

- Node.js 运行时；
- 本地文件系统 API；
- 服务端数据库；
- 运行时图片处理服务；
- 仅桌面端存在的交互方式。

## 11. 当前已有系统与复用方式

### 11.1 UI 基础层

| 系统 | 作用 | 复用要求 |
|---|---|---|
| `UIComponent` | 统一组件 ID、DOM、挂载、可见性和销毁 | 新的结构性 UI 组件应继承或遵循同等生命周期 |
| `UILayer` | 统一 0–5 图层语义 | 新页面保持相同层级顺序 |
| `UIManager` | 注册、显示、销毁页面 | 多页面 UI 通过管理器切换，不手工堆叠 |
| `AssetRegistry` | 按图片、字体、纹理、印章分类注册资源 | 资源不应散落硬编码 |
| `UIAssetManager` | 从 manifest 读取相对路径资源 | 正式资源统一进入资产清单 |

### 11.2 字体系统

| 系统 | 作用 | 复用要求 |
|---|---|---|
| `TypographyConfig` | 定义 Title/Chapter/Body/Handwriting/System 角色 | 新页面只选择角色，不自行发明字体层级 |
| `FontManager` | 注册、加载字体并等待 `document.fonts.ready` | 页面显示前等待字体准备 |
| `TextStyleManager` | 应用文字样式和纹理开关 | 需要对比或低性能模式时关闭纹理 |
| `.typography-texture-enabled` | 墨水吸收、缺墨与纸张融合 | 保持低强度、可关闭 |

### 11.3 Button Framework

现有 `Button` 是唯一正式交互按钮系统，提供：

- `setState(state)`
- `enable()`
- `disable()`
- `setCompleted()`
- 鼠标、触摸、键盘状态处理
- `button:state-change`
- `button:paper-sound-request`
- `memory-button:activate`
- DEBUG 状态日志

传统页面可使用 CSS 纸片外观；Artwork 页面可把完整按钮图片作为子元素。二者必须共享同一状态机。

### 11.4 Memory Report

当前保留两种实现：

#### 数据驱动版

- 页面：`memory-report.html`
- 核心：`MemoryReportScreen`
- 数据：章节 JSON
- 适合需要动态文字、列表、照片和详细状态变化的页面；
- 使用分层 DOM、纸张材质、字体系统和动态组件。

#### Artwork-Based 实验版

- 页面：`memory-report-artwork.html`
- 核心：`ArtworkMemoryReportApp`
- 配置：`memory-report-artwork-config.js`
- 使用完整章节底图；
- 代码仅覆盖记忆清晰度和独立按钮图片；
- 动态区域坐标、百分比位置、按钮位置和裁切全部配置化；
- 不覆盖或删除数据驱动版。

选择原则：

- 视觉稳定、排版固定、章节差异主要由美术决定：优先 Artwork；
- 内容高度动态、需要本地化或大量数据变化：使用数据驱动版；
- 不允许在同一区域同时完整烘焙与完整 HTML 重绘。

### 11.5 Memory 视觉组件

当前可复用组件包括：

- `MemoryPanel`
- `MemorySummary`
- `MemoryClarity`
- `RestoredMemoryList`
- `ForgottenMemoryList`
- `MemoryItem`
- `MemoryThumbnail`
- `PhotoFrame`
- `EmotionText`
- `DateStamp`
- `Stamp` / `MemoryStamp`
- `PaperLayer`

这些组件已经形成“纸张—照片—文字—印章”的视觉语法。新页面应优先组合，而不是重新建立同类组件。

### 11.6 材质与图片系统

- `PaperMaterial`：为组件应用旧纸材质和纹理变量；
- `PhotoMaterial`：根据记忆进度计算照片灰度、棕褐、饱和度、对比度和亮度；
- `MemoryThumbnail`：支持正式图片和 placeholder；
- `UIAssetManager` / `ui_assets.json`：提供统一相对路径；
- Artwork 配置：提供整页底图、按钮图片和坐标。

### 11.7 动画系统

- `MemoryRestorationSequence`：完整记忆恢复流程；
- `PageTransition`：纸页式页面切换；
- `HoverEffects`：统一轻量交互反馈；
- `ui_motion.css`：按钮、照片、印章、翻页等动效 token；
- `memory_restoration.css`：照片显影、文字恢复、印章收尾；
- `prefers-reduced-motion`：所有重要序列的无动画分支。

### 11.8 状态与事件

`MemoryRestoreStateManager` 使用 `localStorage` 保存：

- 章节是否完成恢复；
- 当前清晰度；
- 已恢复记忆列表。

关键事件：

- `MEMORY_RESTORE_LOCK`
- `MEMORY_RESTORE_UNLOCK`
- `EVENT_MEMORY_RESTORED_COMPLETE`
- `memory-report:update`
- `progress-change`
- `button:state-change`
- `button:paper-sound-request`

规范要求：

- 业务状态与视觉状态分离；
- 已完成章节重新进入时直接显示最终状态；
- 未完成章节在首帧先设置起始状态，再开始动画；
- 自动播放 Promise 必须捕获异常并恢复安全状态；
- 页面销毁时清理定时器、事件和临时 DOM。

## 12. 质量与验收清单

### 12.1 视觉

- [ ] UI 看起来属于旧家庭档案，而非现代应用；
- [ ] 色彩暖、低饱和，无科技蓝紫和霓虹；
- [ ] 纸张有纹理、磨损、厚度和叠放关系；
- [ ] 文字像墨迹写在纸上，而非浮在背景之上；
- [ ] 照片具有年代感且与纸面融合；
- [ ] 装饰克制，留白充足；
- [ ] 无默认 HTML 控件视觉。

### 12.2 字体

- [ ] 使用既定字体角色；
- [ ] 标题、正文、手写、数字层级清晰；
- [ ] 字体加载前文本不可见；
- [ ] `document.fonts.ready` 后才显示页面；
- [ ] 慢速网络下没有默认字体闪现；
- [ ] 回退字体仍保持楷体/仿宋/宋体方向。

### 12.3 按钮

- [ ] 复用统一 Button；
- [ ] 支持 default/hover/pressed/disabled/completed；
- [ ] hover 轻微上浮、亮度提升，无弹跳；
- [ ] pressed 在 100–150ms 内自然回缩；
- [ ] disabled 真正禁止交互；
- [ ] 图片按钮没有重复 HTML 文字和纸张背景；
- [ ] Artwork 按钮初始完整显示，无入口淡入；
- [ ] 键盘和触屏可用。

### 12.4 动画

- [ ] 动效有纸张、照片、墨迹或记忆依据；
- [ ] 页面切换约 1 秒，按钮约 400ms；
- [ ] 重要演出期间交互正确锁定；
- [ ] 结束、异常、取消都恢复交互；
- [ ] reduced motion 立即进入最终状态；
- [ ] 不存在先显示最终状态再回退；
- [ ] 不存在无意义的网页式逐项弹出。

### 12.5 资源与兼容

- [ ] 使用相对路径；
- [ ] 静态服务器环境可直接运行；
- [ ] 不依赖 Node、文件系统或服务器 API；
- [ ] 图片无白边、重复文字或错误遮盖；
- [ ] 16:9 与横屏触摸环境正常；
- [ ] Console 无错误；
- [ ] 图片或字体失败时安全降级；
- [ ] 旧版与 Artwork 版互不破坏。

## 13. 一句话规范

> 每一个 UI 元素都应像从老人保存多年的记忆档案中被取出：纸张有时间，墨迹有呼吸，照片有温度，交互像翻阅，恢复像重新想起。
