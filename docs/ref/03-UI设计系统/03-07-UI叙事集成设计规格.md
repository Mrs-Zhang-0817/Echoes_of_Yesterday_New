# 03-07 UI 叙事集成设计规格

> 原始文档：UI 包与叙事补全设计规格  
> 目标：将 UI v1.1 包已验收的记忆恢复报告美术接入现有单 Canvas 游戏

---

## 1. 接入方案

运行本体继续是 `index.html` + 单一 `#gameCanvas`，不嵌入 ZIP 的 DOM 页面、CSS 页面系统或 `window.location.assign` 导航。UI 包的十张报告底图和三张透明按钮作为导入资产，不属于新增生成图片。

## 2. 不可违反的约束（10 条）

1. 运行本体为 `index.html` + 单一 `#gameCanvas`，不嵌入 DOM/CSS 页面系统
2. 不修改根目录 `Echoes_of_Yesterday/` 旧仓库；只在当前 `Echoes_of_Yesterday_New` 工作区操作
3. UI 包的十张报告底图和三张透明按钮是导入资产，不属于新增生成图片
4. 新增生成图片预算 **3 张**，硬上限 6 张；每张必须承担不可由现有帧/裁切/动态效果替代的剧情转折
5. 先复用现有图、ZIP 图、局部裁切、遮罩、显影/褪色、模糊/色调/文字/Canvas 几何和粒子；不得为普通过渡新增整张场景图
6. 不添加第三方依赖；继续支持静态 HTTP 服务、横屏 1280x720 等比 Canvas、触摸和鼠标
7. 每章结束的报告必须由当前 `ChapterManager`、`Overlay`、`InputManager` 和 `ProgressStore` 统一驱动；不能出现双输入层或页面跳离游戏
8. 终章必须形成 100% 闭环
9. 重新开始时保留现有清档回到 Ch1 的语义
10. 不接入真实摄像头识别、OCR、陀螺仪、光线传感器、豆包 API 或网络服务

## 3. 记忆报告接入

ZIP 提供十张完整报告底图和三张透明图片按钮，足够覆盖 Ch1-Ch10 的每个结算页。这些图应导入 `assets/images/report/`，按章节惰性加载与缓存。

**报告视觉方案：** 整图底图 + Canvas 动态清晰度数值/进度 + 单一继续按钮。不复制 ZIP 中 71 个 DOM/CSS/旧 UI 文件。

**共用进度数据（以游戏实际累计值为准）：**

`0 -> 5 -> 15 -> 22 -> 30 -> 40 -> 52 -> 60 -> 72 -> 85 -> 100`

- 每个报告接收：`chapterNumber`、`memoryFrom`、`memoryTo`、`onContinue`
- 报告打开时锁定章节输入
- 底图先完整可见，再在 1.8 秒内从 `memoryFrom` 动画到 `memoryTo`
- **注意：** Ch3 的 `15 -> 22` 与旧 UI 配置（15 -> 15）不同，以游戏实际进度为准

**画面与交互：**
- 每章使用对应完整底图，等比 cover 至 1280x720
- 不在底图已有排版区域重复绘制大段文字
- 只使用"继续昨日"透明按钮作为唯一必需操作（点击区域略大于可见图，120-150ms 轻微下压后调用 `onContinue`）
- "返回主界面"和"查看记忆档案"不在本期开放
- 进度动画包含低强度照片显影/暖色恢复与数字递增；不做奖励爆炸、强闪或现代 HUD
- `prefers-reduced-motion` 时直接显示结束状态并立刻开放继续

**Ch10 终章特殊处理：**
不使用普通结算卡。风铃结尾后依次展示：晨光客厅、粥的蒸汽、已有 Ch1-Ch9 关键图的裁切/显影蒙太奇、白场、最终第十章报告。写入 Ch10 完成和 100% 后再打开报告。"重新开始"沿用清存档后回 Ch1。

## 5. 新生成叙事帧预算（推荐 3 张）

| 序号 | 场景 | 说明 |
|---|---|---|
| 1 | Ch9 闪回：年轻的父亲亲手制作风铃 | 色块重构完成后短暂插入，说明风铃是父女共同记忆 |
| 2 | Ch10 近景：成年女儿端着粥、看向父亲 | 现有端粥人物图仅 250x250，无法承担"认出丫丫"的情绪特写 |
| 3 | Ch10 高潮：父女在晨光里拥抱 | 用于"丫丫"被认出后的无操作高潮与最终报告前的停顿 |

生成项若在实测中被现有高质量素材/局部构图与柔焦完整替代可取消。任何第四张及之后的新增图必须先说明对应剧情节点、现有资产为何不足、以及为何不能以动态解决。

## 7. 验收标准（7 项）

1. Ch1-Ch9 每次完成都出现对应报告底图，点击继续能进入下一章且不跳离 Canvas
2. 报告进度与 `ProgressStore` 一致；Ch10 报告为 100%
3. Ch2/Ch3 闪回严格在前置拼图/路线高亮完全消失之后开始，速度柔和
4. Ch4/Ch10 画面底部不露出错误棕色底板；Ch4 电话、手环为真实图像或可信裁切
5. Ch6 香气粒子的吸附半径、阻尼和目标锁定显著稳定；Ch8 写出"向阳"可通过；Ch9 可完成两段互动并进入 Ch10
6. 默认生成上述三张叙事帧，且总量不超过 6 张；每张都有对应剧情节点和验收截图
7. `npm test`、相关视觉/浏览器流程和 `git diff --check` 通过；Git remote 确认为 `Echoes_of_Yesterday_New.git` 后提交（推送由用户终端执行）

## 8. 明确不在本期实现的外部能力

- 不接入真实摄像头识别、OCR、陀螺仪、光线传感器、豆包 API 或网络服务
- Ch8 为后续摄像头实现留下受控占位和无摄像头回退，不能申请设备权限
- 不新增音频引擎或未经提供的音乐/风铃音频；节奏反馈采用现有震动与视觉节拍，预留音频触发接口
