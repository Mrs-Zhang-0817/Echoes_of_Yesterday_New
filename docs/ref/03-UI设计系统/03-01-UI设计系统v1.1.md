# 03-01 UI 设计系统 v1.1

> 原始文档：《昨日重现》UI Design System  
> 版本：v1.1（基于 UI v1.1 包内内容整理）  
> 基准画布：1280 x 720，16:9，优先适配横屏 HTML5 与抖音互动空间

---

## 1. 核心设计理念

《昨日重现》的 UI 不是覆盖在游戏画面之上的普通 HUD，也不是现代网页、移动应用或任务系统的换肤版本。

**UI 本身就是叙事空间的一部分：** 玩家不是在操作菜单，而是在陪伴一位老人重新翻阅、整理和辨认自己的人生档案。页面、照片、纸片、印章、笔迹和磨损共同承担叙事。

核心设计命题：

> 老人记忆中的旧档案、手写记录与逐渐恢复的人生碎片。

核心关键词：旧照片、泛黄纸张、手写记录、家庭档案、记忆恢复、时间痕迹、人情温度、克制、安静、缓慢。

**玩家心理感受：** 触碰真实保存多年的物件、信息从模糊记忆中逐渐浮现、每次恢复带有珍惜和迟疑的温度、档案虽旧却温暖而非恐怖脏乱、页面有足够停顿和呼吸。

**设计判断三问：** 任何新增 UI 在评审前应回答：
1. 它看起来像一件属于这个家庭档案的实体物件吗？
2. 它的出现与反馈是否像翻阅、触碰、发现或回忆，而非网页响应？
3. 去除背景后，它是否仍与项目的纸张、墨迹、照片和时间感一致？

若任一答案为"否"，应重新设计。

## 2. 视觉语言

### 2.1 色彩体系

整体色彩必须保持暖、旧、低饱和。色彩用于表达纸张年代、墨迹深浅、记忆清晰度和归档状态，不用于制造现代 UI 的强对比刺激。

**核心色：**

| 角色 | 基准值 | 使用说明 |
|---|---|---|
| 页面外背景 | `#2A1B12` | 深暖褐色，承托档案页面 |
| 主标题墨色 | `#4A2E1B` | 最深的手写/标题墨迹 |
| 章节墨色 | `#5A3822` | 章节标签、次级标题 |
| 正文墨色 | `#6B5744` | 描述、记忆条目、说明文字 |
| 手写墨色 | `#686056` | 情绪文字、私人笔记，略灰柔和 |
| 控件墨色 | `#5A3A20` | 按钮与交互标签 |
| 系统小字 | `#3A2415` | 日期、英文副标题、刻度 |

**纸张色范围（不使用单一纯色）：**
- 浅旧纸：`#F1DDAE` 附近
- 中间纸张：`#DFC18A` 附近
- 深度纸边：`#B9894F` 附近
- 氧化阴影：暖棕或深褐，不使用中性纯黑

**辅助色：** 印章红（暗砖红、褪色朱红）、草木绿（灰橄榄绿、旧军绿）、暗金色（黄褐、旧铜金）、未恢复灰（暖灰、灰褐）。

**禁止色彩：** 高饱和蓝/紫/青/荧光色、霓虹/赛博科技色、大面积纯白/纯黑、现代手游奖励金/品质紫/警告红、用鲜艳颜色代替信息层级。

### 2.2 材质语言

所有主要 UI 表面应具有实体材料依据。优先级：① 完整美术资产 > ② 真实纸张/照片/胶带/印章纹理组合 > ③ 轻量 CSS 材质增强 > ④ 纯 CSS 绘制（仅用于动态层和占位）。

纸张特征：可辨识但不过强的纤维或颗粒、泛黄和局部氧化、不规则/磨损/手工裁剪边缘、纸层间轻微暖色阴影、不同纸片间细微色差/旋转/厚度差、胶带/折痕/压痕但不得堆满装饰。

照片特征：轻微褪色/棕褐化/低饱和、旧相纸或纸质边框、与记忆清晰度相关的灰度/模糊/亮度和饱和度变化、合理的压放/粘贴/夹入关系。

**禁止：** 毛玻璃/亚克力/镜面高光、无材质依据的扁平卡片、现代圆角卡片矩阵、默认浏览器边框和阴影、过度脏污导致信息不可读、所有纸片完全相同的纹理和边缘。

### 2.3 阴影与层次

阴影用于说明纸张厚度与叠放关系，不用于制造悬浮面板。颜色使用暖深褐 `rgba(48, 28, 14, .15-.30)`。背景纸层阴影最浅，内容纸片居中，照片和便签可更深。常态阴影柔和、方向统一；hover 只允许轻微增加阴影距离或浓度。禁止黑色硬阴影、彩色外发光和大范围悬浮光圈。

**纸张深度语义：** `background`（档案底页）→ `middle`（次级纸层）→ `content`（主要信息纸片）→ `sticky`（便签/标签）→ `photo`（照片与相框，视觉层级最高）。

## 3. 字体与墨迹系统

### 3.1 字体角色

项目按角色管理字体，正式资源保持以下文件接口：`Title.ttf`、`Chapter.ttf`、`Body.ttf`、`Handwriting.ttf`。

当前字体族接口：`YesterdayTitle`、`YesterdayChapter`、`YesterdayBody`、`YesterdayHandwriting`、`YesterdaySystem`。

自定义字体未就绪时仅允许使用楷体/仿宋/宋体回退链，不得以现代黑体作为主要视觉字体。

### 3.2 标题字体

用途：页面主标题、章节大标题、重要档案标题。特征：手写或旧式记录感、笔画有力不追求完美几何、墨色深（`#4A2E1B`）、有年代感但不过度书法化。

基准：主标题 `clamp(38px, 5vw, 64px)`，字距 `-0.02em`，不透明度约 `.96`；章节标题 `clamp(26px, 3vw, 38px)`，颜色 `#5A3822`，字距约 `.04em`。

### 3.3 正文字体

用途：剧情与档案描述、已恢复/未恢复记忆、提示内容、进度说明。第一优先级可读性，具有仿宋或旧笔记感。

基准：`clamp(18px, 1.8vw, 24px)`，颜色 `#6B5744`，字距约 `.025em`，行高 `1.5-1.7`，不透明度约 `.91`。

### 3.4 手写情绪文字

用途："心里的话"、私人回忆、照片背面式注释、带感情色彩的短句。比正文更松弛，墨色偏灰。

基准：`clamp(20px, 2vw, 28px)`，颜色 `#686056`，字距约 `.035em`，行高约 `1.35-1.5`，不透明度约 `.88`。

### 3.5 数字、日期与刻度

使用正文/章节或既定系统字体角色，百分比可轻微斜体模拟手写记录，日期可使用印章式排列和轻微旋转。禁止七段数码管、科技 HUD 数字、等宽终端字体。

### 3.6 墨迹质感

最终文字应同时处理：暖褐色而非纯黑、角色化字号/字距/行距、轻微不透明度差异、亚像素级暖色阴影模拟墨水吸收与边缘扩散、极轻的对比度和饱和度修正。通过 `.typography-texture-enabled` 总开关启用，必须可关闭以支持性能测试。

### 3.7 字体加载规范

依赖自定义字体的页面不得先显示系统字体再切换。标准流程：文本容器初始隐藏 → FontManager 加载 → 等待 `document.fonts.ready` → 添加 `font-ready` → 约 400ms 低调淡入显示。字体加载失败时应使用既定回退链安全显示。

## 4. 页面布局系统

### 4.1 基准与适配

1280 x 720 基准画布，16:9 比例，横屏居中。使用百分比坐标、`clamp()` 与相对尺寸。不因不同窗口尺寸重新排成现代响应式 Dashboard。安全区域外使用深暖褐背景承托。触屏需保留足够点击面积。

### 4.2 图层规范（0-5 层）

| Level | 图层 | 内容 |
|---|---|---|
| 0 | Background | 固定背景、整页美术底图 |
| 1 | Paper Frame | 档案页、纸框、底层结构 |
| 2 | Static Decoration | 胶带、植物、印章、静态装饰 |
| 3 | Dynamic Content | 照片、进度、列表、可变内容 |
| 4 | Text | 标题和需要独立控制的文字 |
| 5 | Interaction | 按钮、热点、可操作覆盖层 |

非交互图层默认不接收指针事件。

### 4.3 Memory Report 布局（核心页面模板）

- 顶部：章节归档信息、页面主标题、英文副标题、日期印章
- 左上：章节照片（夹在档案中的实体相片）
- 左侧：本章总结、记忆清晰度、情绪文字
- 中央：已恢复记忆列表与归档标记
- 右侧：尚未想起的记忆
- 底部：继续、档案、主页三个纸片式功能按钮

采用非对称三栏，允许轻微偏移和旋转以保持手工档案感。

### 4.4 留白与信息密度

每个纸片只承担一个信息主题，标题与正文之间保留呼吸空间，列表条目宁可减少也不压缩到拥挤，装饰不得填满空白，纸张叠放形成视觉路径而非规则卡片阵列，未恢复区域安静留白等待。

**禁止：** 现代后台式 Dashboard、等宽卡片网格、密集工具栏、过多徽标/数字角标、以分割线填满所有区域。

## 5. 按钮系统

### 5.1 按钮本质

按钮应像贴在档案里的纸片、标签或独立美术贴片，而非网页按钮。复杂按钮视觉优先由美术资产提供。代码负责加载图片、配置位置和点击区域、管理状态、应用轻量 transform/filter/opacity、触发导航/声音/事件。不得在完整美术按钮之上再次生成文字、边框、纸张背景或图标。

### 5.2 唯一状态模型

| 状态 | 语义 | 视觉 |
|---|---|---|
| `default` | 可操作、静止 | 旧纸、低饱和、稳定阴影 |
| `hover` | 记忆被轻微唤醒 | 上浮、略亮、墨色增强 |
| `pressed` | 正在触碰纸片 | 轻微回缩或下压 |
| `disabled` | 暂不可操作 | 降低透明度和饱和度，禁止 hover |
| `completed` | 已完成或已归档 | 稳定纸张、小型旧印章或灰绿标记 |

状态必须由统一 Button 逻辑管理。页面不得直接修改按钮 CSS 类来模拟状态。

### 5.3 各状态详情

- **Default：** 泛黄旧纸或完整按钮图片，暖棕墨色，轻微纸纹与磨损边缘，阴影微弱贴近纸面。Artwork 页面按钮资产在页面出现时立即完整显示，不播放入口淡入。
- **Hover（400ms 标准）：** `translateY(-2px)`，普通纸片保持 `scale(1)`，图片贴片可用 `scale(1.03)`，`brightness` 提高至约 1.08-1.10，`saturate` 恢复至约 1.03。情绪是"记忆被唤醒"。禁止弹跳/大幅缩放/强烈外发光/快速闪白/无限循环呼吸。
- **Pressed（130ms）：** 轻微下压或 `scale(.98)`，阴影收缩、亮度略降，触发 `button:paper-sound-request`。不使用弹簧回弹。
- **Disabled：** 透明度约 .52-.55，降低饱和度和亮度，禁止 hover/点击/键盘激活。动画锁定期间只锁交互，不应制造入口淡入。
- **Completed：** 保持纸张稳定，灰绿/褐绿完成标记，可附加"已归档"印章。禁止亮绿色对勾/金币粒子/庆祝光效。

### 5.4 交互与可访问性

每个按钮必须有稳定 ID 与 `aria-label`。支持鼠标、触屏、Enter 和 Space。disabled 同步设置 `aria-disabled`。交互热点可略大于不规则视觉边缘。状态变化通过 `data-button-state` 表达。新页面复用现有 Button，不得创建第二套按钮状态机。

## 6. 弹窗系统

### 6.1 视觉类型

| 类型 | 推荐物件隐喻 |
|---|---|
| 剧情提示 | 写在纸条或照片背面的短句 |
| 交互提示 | 临时便签、铅笔标记、折角标签 |
| 确认弹窗 | 单独抽出的档案纸或信笺 |
| 错误提示 | 退回标记、批注、褪色红章 |
| 任务提示 | 档案索引条或待整理纸条 |

### 6.2 构建规则

使用纸张、胶带、折角、手写批注、印章等实体语言。主体与遮罩均使用暖色，不使用纯黑半透明遮罩。标题简短，正文克制。主次操作都沿用统一 Button。错误状态仍保持温和。

### 6.3 动画

推荐：轻微展开、小幅 `translateY`、极轻角度校正、纸张从叠层中抽出、360-620ms 自然出现。禁止从中心大幅 scale、商城礼包式弹出、橡皮筋/果冻/弹簧动画。

## 7. 动画与动效

### 7.1 核心原则

动效关键词：慢、自然、有呼吸、有物理依据、服务阅读、服务记忆恢复叙事。动画不应证明"系统响应很快"，而应表达纸张/照片/墨迹和记忆正在发生变化。

### 7.2 时间尺度

| 类型 | 推荐时长 | 当前基准 |
|---|---|---|
| 按压反馈 | 100-150ms | 130ms |
| Hover | 300-500ms | 400ms |
| 小型照片/文字显现 | 300-800ms | 300-800ms |
| 印章动作 | 700-1600ms | 720-1600ms |
| 页面翻页/切换 | 800-1200ms | 900-1000ms |
| 照片清晰度恢复 | 1-2s | 约 1200-2000ms |
| 完整记忆恢复演出 | 按叙事需要 | 长于普通 UI，分阶段 |

### 7.3 缓动

纸张与按钮：`cubic-bezier(.22, .7, .25, 1)`；页面翻动：`cubic-bezier(.38, .05, .16, 1)`；墨迹/亮度/透明度：柔和 ease-out 或 ease-in-out。避免 `linear` 用于明显位移、弹簧/回弹/overshoot、多个元素逐条飞入。

### 7.4 记忆恢复动效

必须表现连续恢复过程：纸张从沉寂到温暖 → 缩略图像照片显影 → 照片从灰暗模糊到较清晰 → 文字从淡缺失到可辨 → 清晰度数字与进度同步 → 完成印章收尾 → 情绪文字安静出现。

**避免：** 奖励结算、粒子爆发、元素机械逐个弹出、为满足时长人为切割节奏、先显示最终状态再回退。

### 7.5 MEMORY_RESTORE_LOCK

重要演出开始时应发布 `MEMORY_RESTORE_LOCK`，锁定返回、章节切换、主菜单、手动盖章等操作。结束或异常恢复时必须发布 `MEMORY_RESTORE_UNLOCK`。页面关闭或取消后不得继续执行计时器、Promise 或 DOM 动画。

### 7.6 减少动画

所有新动效必须支持 `prefers-reduced-motion: reduce`：直接进入安全最终状态，JS 不得继续等待完整演出时长，保持内容/状态/导航完整，不得仅在 CSS 中缩短动画而让业务 Promise 继续等待。

### 7.7 禁止动效

快速弹窗、闪烁、频繁摇晃、大幅飞入、现代游戏 HUD 扫描线、无叙事意义的循环动画、大量 JS 高频写 DOM、同一状态同时由 CSS 与 JS 分别驱动而冲突。

## 8. 图片与美术资产规范

- **背景图：** 16:9 按完整画布输出，保留纸张/照片/装饰和静态排版时明确哪些区域由代码动态覆盖，动态区域不得在底图中重复烘焙数字/文字/进度。
- **按钮图片：** 使用带透明通道的完整按钮 PNG，透明边缘应干净，资产必须完整遮盖底图中的旧按钮，位置与裁切使用配置管理。
- **照片：** 保持原始宽高比（`object-fit: cover` 或 `contain`），老化效果与故事年代一致，低清晰度应结合灰度/低饱和/低对比/暗度和纸面旧化而非简单模糊。
- **纸张与纹理：** 纹理可平铺或覆盖避免明显接缝，同一页面可共享纸张家族但应有色调/边缘/旋转差异，运行时机采用轻量 CSS 避免移动端持续 Canvas 运算。
- **印章与标记：** 使用褪色朱红/暗绿/棕色，边缘允许缺墨和不完整，角度小幅偏转，动画包含落下/轻微回弹/墨迹扩散，一次演出只创建并管理一个印章实例。
- **资源交付检查（8 项）：** 命名稳定、尺寸坐标明确、PNG 透明通道真实、无意外白边、动态覆盖区域已清空、文字烘焙已标注、压缩后无色带锐化边、HTML5 可直接通过相对路径读取。

## 9. 交互设计原则

所有交互服从同一叙事隐喻：**老人正在重新翻阅自己的记忆档案。**

| 玩家行为 | 叙事表达 |
|---|---|
| Hover | 手指靠近纸片，沉睡的记忆轻微被唤醒 |
| 点击 | 按下、掀起或确认一张纸 |
| 页面切换 | 翻页、抽出下一份档案 |
| 发现线索 | 找到旧照片、批注或被遗忘的物件 |
| 恢复记忆 | 照片显影，文字与色彩逐渐清晰 |
| 完成 | 盖章归档，安静确认 |
| 不可操作 | 纸片褪暗或暂时不可触碰 |
| 错误 | 档案批注或退回标记，而非系统警报 |

反馈必须明确但不应吵闹。声音建议使用纸张摩擦、轻触、翻页、木桌和印章等拟物声音，不使用电子提示音。

## 10. 开发构建规范

**新增 UI 强制流程（10 步）：** 明确实体隐喻 → 检查复用组件 → 选择 HTML 或美术资产方案 → 使用既有字体角色/颜色/图层 → 使用统一 Button → 配置化位置/尺寸/资源路径 → 接入键盘/触摸/ARIA → 接入 reduced motion → 验证 16:9/移动端性能/相对路径 → 与旧页面确认无现代 UI 语言。

**禁止事项（10 条）：** 新建另一套 Button 系统、页面直接操作按钮 CSS 状态、使用浏览器默认按钮/输入框/边框作为正式视觉、在各页面复制不同色值和动画参数、使用 Node/文件系统/服务器 API 作为运行时依赖、把复杂美术完全用 CSS 渐变重画、将整页所有内容烘焙进图片后又用 HTML 重复覆盖、未等待字体就显示自定义字体文本、忽略取消/异常/reduced motion 生命周期、重构现有 Memory 核心解决单一页面视觉问题。

**运行环境必须支持：** 浏览器 HTML5、抖音互动空间、静态文件部署、相对路径资源、DOM/CSS 动画/Font Loading API/fetch() 静态 JSON、localStorage 不可用时安全降级。不得依赖 Node.js 运行时、本地文件系统 API、服务端数据库、运行时图片处理服务、仅桌面端存在的交互方式。

## 11. 当前已有系统与复用方式

### UI 基础层

| 系统 | 作用 |
|---|---|
| `UIComponent` | 统一组件 ID/DOM/挂载/可见性/销毁 |
| `UILayer` | 统一 0-5 图层语义 |
| `UIManager` | 注册/显示/销毁页面 |
| `AssetRegistry` | 按图片/字体/纹理/印章分类注册资源 |
| `UIAssetManager` | 从 manifest 读取相对路径资源 |

### 字体系统

`TypographyConfig`（定义 5 种字体角色）、`FontManager`（注册/加载字体）、`TextStyleManager`（应用文字样式和纹理开关）、`.typography-texture-enabled`（墨水吸收/缺墨与纸张融合）。

### Button Framework

统一 Button 提供：`setState(state)`、`enable()`、`disable()`、`setCompleted()`、鼠标/触摸/键盘状态处理、`button:state-change`、`button:paper-sound-request`、`memory-button:activate`、DEBUG 状态日志。

### Memory Report（两种实现）

- **数据驱动版**（`memory-report.html` + `MemoryReportScreen`）：适合动态文字/列表/照片和详细状态变化的页面。
- **Artwork-Based 实验版**（`memory-report-artwork.html` + `ArtworkMemoryReportApp`）：使用完整章节底图，代码仅覆盖记忆清晰度和独立按钮图片。动态区域坐标/百分比位置/按钮位置和裁切全部配置化。

选择原则：视觉稳定/排版固定/章节差异主要由美术决定 → Artwork；内容高度动态/需要大量数据变化 → 数据驱动版。不允许在同一区域同时完整烘焙与完整 HTML 重绘。

### Memory 视觉组件（可复用）

`MemoryPanel`、`MemorySummary`、`MemoryClarity`、`RestoredMemoryList`、`ForgottenMemoryList`、`MemoryItem`、`MemoryThumbnail`、`PhotoFrame`、`EmotionText`、`DateStamp`、`Stamp`/`MemoryStamp`、`PaperLayer`。

### 材质与图片系统

`PaperMaterial`（旧纸材质和纹理变量）、`PhotoMaterial`（根据记忆进度计算照片参数）、`MemoryThumbnail`（正式图片和 placeholder）、`UIAssetManager`/`ui_assets.json`（统一相对路径）、Artwork 配置（整页底图/按钮图片/坐标）。

### 动画系统

`MemoryRestorationSequence`（完整记忆恢复流程）、`PageTransition`（纸页式页面切换）、`HoverEffects`（统一轻量交互反馈）、`ui_motion.css`（动效 token）、`memory_restoration.css`（照片显影/文字恢复/印章收尾）、`prefers-reduced-motion`（无动画分支）。

### 状态与事件

`MemoryRestoreStateManager` 使用 `localStorage` 保存章节完成状态、当前清晰度、已恢复记忆列表。关键事件：`MEMORY_RESTORE_LOCK` / `MEMORY_RESTORE_UNLOCK` / `EVENT_MEMORY_RESTORED_COMPLETE` / `memory-report:update` / `progress-change` / `button:state-change` / `button:paper-sound-request`。

规范要求：业务状态与视觉状态分离、已完成章节重新进入时直接显示最终状态、未完成章节在首帧设置起始状态再开始动画、自动播放 Promise 必须捕获异常并恢复安全状态、页面销毁时清理定时器/事件/临时 DOM。

## 12. 质量与验收清单

### 视觉（7 项）
UI 属于旧家庭档案而非现代应用；色彩暖/低饱和；纸张有纹理/磨损/厚度/叠放；文字像墨迹写在纸上；照片有年代感；装饰克制；无默认 HTML 控件视觉。

### 字体（6 项）
使用既定角色；标题/正文/手写/数字层级清晰；字体加载前文本不可见；`document.fonts.ready` 后才显示；慢速网络下无默认字体闪现；回退仍保持楷体/仿宋/宋体。

### 按钮（8 项）
复用统一 Button；5 种状态完整；hover 无弹跳；pressed 自然回缩；disabled 真正禁止交互；图片按钮无重复 HTML；Artwork 按钮无入口淡入；键盘和触屏可用。

### 动画（7 项）
有纸张/照片/墨迹或记忆依据；页面切换约 1s/按钮约 400ms；重要演出期间交互正确锁定；结束/异常/取消恢复交互；reduced motion 立即进入最终状态；不存在先显示最终状态再回退；不存在无意义的网页式逐项弹出。

### 资源与兼容（8 项）
使用相对路径；静态服务器可直接运行；不依赖 Node/文件系统/服务器 API；图片无白边/重复文字/错误遮盖；16:9 与横屏触摸正常；Console 无错误；图片或字体失败时安全降级；旧版与 Artwork 版互不破坏。

## 13. 一句话规范

> 每一个 UI 元素都应像从老人保存多年的记忆档案中被取出：纸张有时间，墨迹有呼吸，照片有温度，交互像翻阅，恢复像重新想起。
