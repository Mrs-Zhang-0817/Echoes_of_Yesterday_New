## 二、敏捷策略：Walking Skeleton

### 核心原则

- **Phase 1 就建好 ChapterManager + 10 个占位章节**——任何时刻都有一个"10 章全线可导航"的完整产品
- 之后每个关卡独立开发，完成一个就"点亮"一个（用自己的 `chapters/chNN.js` 替换占位），不碰框架、不碰其他关卡
- **为什么不做大爆炸集成**：10 个关卡的输入冲突、生命周期、坐标/DPR 差异会在最后 1 小时集中爆发，骨架期定好统一接口，后面填关卡就是填空

### 统一接口

每章必须实现：

```javascript
class ChapterNN {
  constructor(game)
  onEnter()
  onExit()
  update(dt)
  render(ctx)
  get isComplete()
}
```

## 五、技术决策

| # | 决策 | 详情 |
|---|------|------|
| 1 | JS/CSS 全内联单 `<script>` | 兼容妙搭与旧 WebView，图片走 zip 内相对路径 |
| 2 | 开发态模块化 | `chapters/chNN.js` + `core/`，`build.js` 拼接 |
| 3 | 骨架先行 | 未实现的关为"占位章节"——程序化背景 + 文案 + 长按 1s 继续 |
| 4 | 进度 localStorage | key `ye_progress_v1`，存 `{chapter, memory, completed:[], ts}` |
| 5 | 无音效 | 省体积+autoplay 限制，震动 navigator.vibrate 可选 |
| 6 | 横屏 fixed 1280×720 | 竖屏全屏遮罩提示旋转，DPR 固定 1280×720×DPR |
| 7 | ctx.filter 兜底 | 离屏 Canvas 预生成灰度，不依赖运行时 ctx.filter |
| 8 | 文案红线 | 禁用"游戏/通关/玩家/输赢"，统一"章节/片段/继续/体验" |
| 9 | 错误兜底 | try/catch + 自绘错误弹层；图片加载失败→重试1次→ErrorModal |
