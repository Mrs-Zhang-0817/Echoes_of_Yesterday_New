# 昨日重现 · 完整游戏设计文档

> 本文档是整个项目的顶层设计总结，覆盖：为什么做这个游戏、目标用户是谁、核心体验是什么、技术架构、开发计划与包体预算。

---

## 一、核心定位

### 项目定义

- **项目名称**：昨日重现 / Echoes of Yesterday
- **项目类型**：以阿尔茨海默症为主题的叙事向 HTML5 移动端游戏
- **平台**：飞书妙搭（Spark / Miaoda）、抖音互动空间
- **设计分辨率**：1280×720 横屏（Canvas 2D）
- **技术栈**：纯 HTML5 Canvas 2D，零外部运行时依赖，ES Modules 开发态 + 构建时内联为单文件

### 为什么做这个游戏

- **主题**：让玩家通过互动体验，亲身体验阿尔茨海默症患者在记忆模糊世界中的挣扎与温情
- **社会价值**：提高公众对阿尔茨海默症（及其非药物干预方法）的认知和理解
- **叙事目标**：讲述一个父亲在遗忘中找回女儿"丫丫"的故事，传递"只要爱不迷路"的情感内核

### 目标用户

- 移动端轻度游戏玩家（竖屏→横屏体验模式）
- 关注社会议题、情感叙事的用户群体
- 抖音互动空间 / 飞书平台用户，年龄层以 20-45 岁为主
- 阿尔茨海默症患者家属/照护者（非主力目标，但希望产生共鸣）

### 核心体验

- **10 章叙事互动**：从"儿时的回忆"到"爱，从不迷路"的情感弧线
- **"互动不是炫技，而是让玩家亲身体验症状"**：每个互动对应一种病理表现（记忆错乱、空间迷失、失认症、镜像失认等）
- **记忆解锁系统**：从 0% 到 100% 的渐进式记忆恢复进度条
- **纯 Canvas 渲染**：无 DOM 依赖、无外部库的轻量化体验

## 二、关键设计决策总表

| 决策 | 选择 | 原因 |
|------|------|------|
| 渲染方案 | Canvas 2D，1280×720 逻辑分辨率 | 单一绘制表面，固定尺寸简化横屏适配 |
| 技术架构 | 零外部依赖，ES Modules + 内联构建 | 兼容抖音互动空间/妙搭的旧 WebView，无网络请求 |
| 交互输入 | Pointer Events 统一封装 | 同时支持触屏和鼠标 |
| 章节管理 | ChapterManager + 10 个独立 chapter 模块 | 并行开发，互不干扰 |
| 叙事 vs 互动 | 状态机驱动，叙事段→互动段交替 | 每关统一结构：背景+文案+1个核心互动+过渡 |
| 进度存储 | localStorage（key: ye_v1_progress） | 纯前端方案，无需后端 |
| 弹层 | Canvas 自绘 Overlay（排他激活） | 同一时刻只允许一个弹层 |
| 失败兜底 | 3 次失败自动辅助 / 超时自动通过 | 防止软卡关 |
| 音效 | 本次不上线 | 省体积 + autoplay 限制；BGM 规划 19 段留待后续 |
| 开发态 | 模块化 ES Modules | 4 人并行零冲突 |
| 构建态 | build.cjs 拼接为单文件 HTML | 兼容平台约束 |

## 三、人物设定

### 父亲（主角）

- **身份**：罹患阿尔茨海默症的老人，以第一人称体验整个故事
- **特征**：记忆日渐模糊，时常退行到"小孩"的心理状态
- **情感弧线**：从迷失困惑→挣扎抗拒→逐渐接受→温暖和解
- **第一人称视角**：玩家全程代入父亲的感官体验

### 丫丫（女儿）

- **身份**：父亲的女儿，成年女性
- **特征**：眼角带细纹、鬓角花白的"中年妇女"
- **玩家误解设计**：玩家在前 9 章始终不认不出她是女儿——这正是阿尔茨海默症的病理表现（面孔失认）
- **第十章的真相**：所有碎片拼合，认出"丫丫"
- **角色功能**：象征亲情桥梁和家的温暖

### AI 管家

- **定位**：常驻 UI 右上角的柔和提示辅助
- **功能**：在玩家迷失时给出温和线索提示

## 四、记忆进度条系统

### 核心机制

- 每章完成后写入累计记忆值（localStorage key: `ye_v1_progress`）
- 采用 `max(旧值, memory)` 写入（累计、不回退）
- Ch10 终章记忆报告页读取全部数据，呈现完整档案

### 记忆进度各章数值

| 章节 | 标题 | 完成后记忆值 | 备注 |
|------|------|-------------|------|
| Ch1 | 序曲·镜前 | 5% | 纯叙事，自动完成 |
| Ch2 | 接女儿放学 | 15% | 3×3 拼图互动 |
| Ch3 | 迷途 | 22% | 迷宫连线 |
| Ch4 | 警局 | 30% | 多阶段状态机 |
| Ch5 | 归家 | 40% | 电梯按钮迷宫 |
| Ch6 | 温暖日常 | 52% | 触觉+气味拼图 |
| Ch7 | 惊悚夜醒 | 60% | 黑暗找门锁 |
| Ch8 | 自我和解 | 72% | 签字笔画识别 |
| Ch9 | 风铃 | 85% | 音符拖拽+音游 |
| Ch10 | 认出 | 100% | 终局记忆报告 |

### 记忆报告页

- **渲染位置**：Ch10 终章 `finalReport` 阶段
- **内容**：米黄纸张底板 + 印章 + 标题"记忆恢复档案" + 10 章列表（各章进度条+完成标记）+ 全局记忆进度条 + "重新开始"按钮

## 五、技术架构

### 运行形态

```
开发态: index.html → <script type="module" src="src/main_new.js"> → src/core/ + src/chapters/
上线态: build.cjs 拼接 → build_out/index.html（单文件+图片相对路径）
```

### 核心引擎模块

| 模块 | 文件 | 职责 |
|------|------|------|
| Game | `core/Game.js` | rAF 主循环，dt 上限 0.1s |
| InputManager | `core/InputManager.js` | Pointer Events 封装，坐标转换 |
| ChapterManager | `core/ChapterManager.js` | 章节注册/切换/0.3s fade 过渡 |
| Loader | `core/Loader.js` | 图片预加载+进度回调 |
| Overlay | `core/Overlay.js` | Canvas 自绘弹层（遮罩+卡片+按钮） |
| ProgressStore | `core/ProgressStore.js` | localStorage 进度存储 |

### Chapter 接口契约

```javascript
class ChapterNN {
  constructor(game)     // 接收 game 对象
  onEnter()              // 注册 input handlers
  onExit()               // 注销 input handlers
  update(dt)             // 每帧更新
  render(ctx)            // Canvas 2D 绘制
  get isComplete()       // 返回 boolean
}
```

### 目录结构

```
Echoes_of_Yesterday_New/
├── index.html               # 开发入口
├── build.cjs                # 构建脚本
├── package.json             # 仅 Playwright 测试依赖
├── assets/images/           # 17 张运行时图片
├── src/
│   ├── main_new.js          # 统一入口
│   ├── core/                # 引擎核心（6 模块）
│   ├── chapters/            # 10 章实现
│   ├── utils/               # 工具函数
│   ├── data/                # 章节元数据
│   ├── narrative/           # 叙事活动模块（闪回/蒙太奇）
│   └── dev/                 # 调试 API
├── docs/                    # 项目文档
├── tests/                   # Playwright E2E 测试
└── build_out/               # 构建产物
```

### 调试接口

- 快捷键 `D`：打印快照
- 快捷键 `F`：强制完成当前章节
- 快捷键 `1-0`：跳转到对应章节
- 全局对象 `window.__debug__`：供 Playwright 测试读取

## 六、过渡设计

### 章节间过渡

- 统一 0.3s 黑屏淡入淡出（`rgba(0,0,0,alpha)` 铺满）
- 终端用户不能交互——渲染顺序确保弹层在章节之上

### 竖屏提示

- `createRotateHint()`：竖屏时显示"请旋转设备"遮罩
- 不实现响应式缩放，横屏铺满即可

### 转场 blocked 保护

- 章节完成 → Overlay 弹出 → phase 置 `blocked` → 用户点击按钮后 `next()`
- 目前无超时保护（已知问题）
