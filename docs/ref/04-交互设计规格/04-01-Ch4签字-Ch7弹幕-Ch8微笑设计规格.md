# Ch4 签字迁移、Ch7 弹幕与 Ch8 镜中微笑设计规格

## 不修改的限制清单

以下模块在本次实现中**保持不动**，不新增、不修改、不删除任何代码：

- `src/narrative/` 及其所有子文件
- 报告资产（MemoryReportScreen 等相关模块）
- `ChapterManager`
- `Overlay` 及其测试

## 约束说明

- 只修改 Ch4、Ch7、Ch8 的章节实现、关卡元数据、入口资源注册，并新增与互动直接相关的模块、模型和回归测试。
- 引入 `face-api.min.js` 与 TinyFaceDetector、表情识别模型；不使用压缩包内的 HTTPS 服务器和证书文件。
- 摄像头视频只在浏览器本机内存中供检测和 Canvas 预览使用；不上传、不存储。
- 用户主动点击"开启摄像头"才申请权限，离开/完成后停止所有媒体轨道。

## Ch4 警局签字还原

**流程：** `电话 → 来电演出 → 签字还原 → 手环揭示 → 结算`

- 签字保留原有笔画畸变、清除、提交、提示和可完成性规则。
- 完成时不自行写入第 8 关存档，而是把控制权交回 Ch4。
- Ch4 完成后写入第 4 关进度与当前统一报告进度。

## Ch7 暗夜的微光弹幕气泡

**流程：** `开场 → 安抚气泡 → 找门锁 → 开门 → 结算`

- 气泡沿现有 1280x720 Canvas 右侧进入，最多 5 个并发。
- 点击命中后不再参与弹幕移动，以 0.45 秒飞向胸口位置呈现微光粒子。
- 收集 4 个即开始现有找门锁阶段。
- 20 秒内未收集足够时自动补足，避免卡关。
- 原门锁的 60 秒兜底保留。

**新增文件：**
- `src/interactions/DanmakuBubbleField.js`：基于现有弹幕包思想，负责生成、命中、飞向胸口和绘制，不依赖 DOM。

## Ch8 走廊的镜子微笑判定

**流程：** `镜中陌生人 → 用户选择/启动摄像头 → 微笑判定或挥手回退 → 裂纹消退、陌生人变为微笑 → 结算`

### 判定规则

- 模型预加载失败或不支持 `getUserMedia`：直接显示挥手引导。
- 相机权限被拒绝、设备不可用、视频 8 秒未就绪：切换到挥手引导，不重复弹权限请求。
- 摄像头路径每 200ms 检测一次，只接受单张脸的 happy 分数。
- **核心判定条件：连续 1.5 秒达到 happy >= 0.6** 才完成。

### 挥手回退规则

- 要求触点从左向右且**横向距离不少于 35% 画布宽度**。
- 纵向波动存在，避免普通点击误过关。
- 提供与微笑通关等同的通过路径，保证摄像头不可用时游戏可玩。

**新增文件：**
- `src/interactions/SmileDetector.js`：封装模型加载、视频生命周期和表情采样；不负责章节 UI。

**替换/修改文件：**
- 替换 `src/chapters/ch08_sign.js` 的章节实现为镜中微笑流程，文件名保留避免注册和外部链接同时变化。
- 将 face-api 脚本和模型放入 `assets/vendor/face-api/`，在 `index.html` 的模块入口前加载脚本。

## 风险与约束

- **人脸识别依赖安全上下文（HTTPS 或 localhost）和用户授权**；这是浏览器限制，挥手回退保证游戏不因此不可玩。
- 提供的 face-api 包未包含许可证说明；公开发布前应补充上游许可证与归属核验。
- 现有运行时将 Ch8 注册为 `ch08`，但源文件名是 `ch08_sign.js`；保持文件名不动，减少与 WorkBuddy 整理的重命名冲突。
