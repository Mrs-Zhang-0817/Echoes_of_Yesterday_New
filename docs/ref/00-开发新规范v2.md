# 《昨日重现》开发新规范 v2.0

> 基于黑客松阶段（7/28-30）的经验教训和生产问题，修正后的开发规范。
> 取代旧 `docs/DEVELOPMENT_STANDARD.md` 和 `docs/unified-tech-spec-v1.0.md` 的相关部分。

---

## 一、核心约束（不变）

1. **单 Canvas 2D** — 所有游戏画面在 `<canvas id="gameCanvas">` 内绘制，禁止 DOM 弹层/UI
2. **1280x720 逻辑分辨率** — `ctx.scale(ratio, ratio)` 居中适配，DPR 强设为 1
3. **Pointer Events** — `pointerdown/pointermove/pointerup` 统一输入层
4. **Canvas 自绘弹层** — 用 Overlay 模块，禁止 `window.alert/confirm/prompt`
5. **相对路径图片** — `assets/images/xxx.png`，禁止绝对路径/CDN
6. **`localStorage` 前缀 `ye_`** — 如 `ye_progress_v2`
7. **零外部依赖** — 禁止 npm 运行时包、禁止 CDN、禁止 `eval/new Function`
8. **禁用"游戏"字样** — 按钮不写"游戏"用"故事"/"旅程"/"记忆"

## 二、从 Bug 中沉淀的硬规则

### 2.1 章节开发契约

```js
class ChXX {
  onEnter()  // 初始化：创建对象、注册事件、播放开场
  onExit()   // 清理：移除事件监听、停止动画帧、释放引用

  update(dt) // 逻辑更新（不在这里绘图）
  render(ctx)// 绘图（不在这里更新逻辑）

  isComplete() // 返回 boolean，驱动 ChapterManager 流程
}
```

**强制约束：**
- `update` 和 `render` **必须分离**，禁止同一个函数里既算逻辑又画图
- `onExit` 必须 `removeEventListener` 所有在 `onEnter` 中注册的事件
- `isComplete` 完成标记写入后，`onExit` 必须被调用一次

### 2.2 输入与事件

- 所有 `pointer...` 事件用 `InputManager.setHandlers` 注册，不用 `canvas.addEventListener`
- `handleDown` 中**必须先判按钮区域，再判交互区域**（ch08 Bug 教训）
- 每次交互结束后必须 `e.preventDefault()`，防滚动/缩放

### 2.3 进度与存档

- **每一章** 的完成路径上必须且只调用一次 `ProgressStore.markChapterComplete(chapterId)`
- 以 `chapters.json` 中的 `memoryUnlock` 值为基准，**不能硬编码百分比**
- `ProgressStore.getCurrentChapter()` 不能从已完成章节开始（已修复：读下一章）

### 2.4 图像加载

- Loader 中**每张图片**必须链式（`img.onload/onerror`），单张失败走占位图
- manifest 中的图片**不一定全在用**，新加图片必须同时确认代码引用
- 漫画用展平路径 `comic_flat/chXX_YY.jpg` 避免中文路径问题

### 2.5 Overlay 弹层

- Overlay 的 `onEnter` 和 `show` 是两回事：`show` 只是显示，不要在 `show` 里写业务逻辑
- 一次只允许一个弹层处于 `active` 状态
- "下次/继续"按钮是所有弹层的标配

## 三、资料使用规则

### 3.1 权威索引

- 所有存档资料以 `docs/ref/` 为准
- 新增资料必须按编号规则放入对应目录，并更新 `docs/ref/README.md`

### 3.2 飞书 vs 本地

- 飞书文档是「策源地」，本地实现有时会偏离
- 开始任何新功能前，先读 `docs/ref/02-策划案与设计文档/02-05-策划案与现状差异清单.md`
- 实现偏离策划案时，在对应章节代码顶部加注释说明偏离原因

### 3.3 智能体协作

- 多智能体并行时，用独立的命名空间（`chXX-*`）避免文件冲突
- 同一文件被多个智能体修改 → 用 git diff 逐项确认合并
- 智能体产出检查清单（开发结束后必查）：
  - [ ] 新增代码匹配现有风格
  - [ ] 没有覆盖已有的 utils/函数
  - [ ] console.log 已清理
  - [ ] 图片路径正确（非中文路径优先）
  - [ ] ProgressStore.markChapterComplete 已调用
  - [ ] 所有事件监听有对应的 removeEventListener

## 四、重构建议清单（基于资料碰撞发现）

### P0 — 影响游戏可玩性

| 问题 | 描述 | 位置 |
|------|------|------|
| Ch3 核心玩法偏离 | 策划案是分支选路+迷宫连线，实现是自动导航 | `src/chapters/ch03_maze.js` |
| Ch5 核心玩法偏离 | 策划案数字键盘输503->声相定位，实现是电梯按钮向日葵 | `src/chapters/ch05_door.js` |
| 代码合并未经验证 | 多智能体并行产出，存在部分代码未真机测试 | 全局 |

### P1 — 架构问题

| 问题 | 描述 |
|------|------|
| 两套弹层系统并存 | Overlay 模块 vs 各章自绘弹层，需统一 |
| chapters.json 脱节 | 某些章节的 memoryUnlock 与代码硬编码值不一致 |
| Loader 与 ChapterManager 耦合过紧 | 所有章节都加载完才启动，体验上首屏等待久 |
| 无音频系统 | AudioManager 在旧仓库，当前项目未接入 |

### P2 — 可维护性

| 问题 | 描述 |
|------|------|
| manifest 注册了31张从未渲染的图 | 预加载浪费约 18MB 带宽 |
| 8张警局图全注册但只用01 | 白白加载7张 |
| 无单元测试覆盖新增章节 | 测试集中在Ch2拼图 |
| ch08_sign.js 有独立 rAF/DPR/事件系统 | 与全局架构重复，需要重构进统一架构 |
