# 05-01 开发规范 v1.0

## 概述

本规范是《昨日重现》项目的最高开发守则，覆盖渲染、输入、架构、打包等全部技术环节。所有智能体在修改或新增代码前，必须以本规范为准绳。

全作品约束：**一片 Canvas（1280x720），零 DOM UI，零外部依赖**。

---

## 一、技术铁律（9 条）

| 项 | 规定 | 违规后果 |
|----|------|----------|
| 渲染 | **纯 Canvas 2D**，全作品只有一个 `<canvas>` | 抖音互动空间不认 DOM UI |
| 分辨率 | **1280x720 逻辑坐标**，等比缩放适配所有屏幕 | 出现黑边/偏移 |
| 输入 | **Pointer Events**，走 `InputManager` 统一分发 | touch 和 mouse 行为不一致 |
| 弹层 | **Canvas 自绘**，禁止 `alert/confirm/prompt` | 抖音直接拦截弹窗 API |
| 坐标 | 所有代码用 1280x720，不碰 DPR | 缩放后坐标错位 |
| 图片 | 全本地**相对路径**，零网络请求 | 线上加载失败 |
| 进度 | `localStorage`，key 前缀 `ye_v1_` | 与其他应用 key 冲突 |
| 打包 | 单文件 `index.html`，ES Modules 全部内联 | 妙搭不认 ES Modules |
| 文案 | 禁用"游戏/玩家/输赢"，用"章节/体验/继续" | 违反抖音内容规范 |

### 兼容兜底策略

- `ctx.filter` 不可靠（iOS Safari < 18）→ 效果用**离屏 Canvas** 预生成灰度/褪色版
- `navigator.vibrate` → `try/catch` 包裹（iOS 不支持时静默跳过）
- 图片加载失败 → 自动重试 1 次 → 仍失败则自绘占位图形
- 全局 `try/catch` 兜底 → 捕获异常时在 Canvas 上绘制提示文字，不白屏

## 二、Chapter 接口契约（5 方法）

每一章的 JS 文件导出一个类，实现以下 5 个方法：

```javascript
export class ChapterNN {
  constructor(game) {
    // game = { canvas, ctx, width:1280, height:720, images, input, progress, overlay }
  }

  onEnter() {}          // 注册 input.setHandlers()，初始化状态变量
  onExit() {}           // 清空所有 handler，清理 timer / interval
  update(dt) {}         // dt 秒，已 cap 最大 0.1s（防止跳帧）
  render(ctx) {}        // 绘制到 ctx，坐标系 1280x720

  get isComplete() {}   // 返回 boolean，ChapterManager 轮询读取
}
```

**核心约束：**

- `onEnter` / `onExit` 必须严格配对——`onExit` 必须清空 `input.setHandlers()`（无参调用）
- `update` 中只做状态计算，不做渲染；`render` 中只做绘制，不改状态
- `isComplete` 是只读 getter，不允许在其中修改任何状态
- 章节之间不互相引用，不访问其他章节的内部状态或 DOM
- 需要触发章节切换时，统一调用 `game.chapterManager.next()`

## 三、game 全局对象

所有章节共享同一个 `game` 对象：

```javascript
const game = {
  canvas,          // HTMLCanvasElement
  ctx,             // CanvasRenderingContext2D
  width: 1280,     // 逻辑宽度（永远不变）
  height: 720,     // 逻辑高度（永远不变）
  images: {},      // Loader 预加载的 { key: HTMLImageElement }
  input,           // InputManager 实例
  chapterManager,  // ChapterManager 实例
  progress,        // ProgressStore 实例
  overlay,         // Overlay 实例（Canvas 自绘弹层）
};
```

**规则：** 任何章节不得覆盖 `game` 属性，不得持有 `game` 的持久引用导致内存泄漏。

## 四、输入规范

```javascript
// 在 onEnter 中注册
this.game.input.setHandlers({
  down(point)  { /* point = { x, y, pointerId, pointerType } */ },
  move(point)  { /* x, y 已是 1280x720 逻辑坐标 */ },
  up(point)    {},
  cancel()     {},
});
```

- 所有 `point.x / point.y` 已由 `InputManager` 自动转换为 1280x720 坐标系，章节代码直接使用
- 禁止在 Chapter 中自己调用 `addEventListener`
- `onExit` 中调用 `game.input.setHandlers()`（不传参数 = 清空所有 handler）

## 五、弹层规范

```javascript
game.overlay.show({
  type: 'complete',                  // 'prompt' | 'complete' | 'error'
  title: '记忆恢复了一些……',
  message: '但那抹色彩，终究会慢慢褪去……',
  buttons: [
    { text: '继续下一章节', action: () => game.chapterManager.next() }
  ],
});
```

**弹层铁律：**

- 全屏半透明黑色遮罩 + 居中圆角卡片（全部 Canvas 自绘）
- 同时只允许一个弹层处于激活态
- 结算弹层必须有"下一步"按钮
- 按钮文字不使用"游戏/通关/胜利"字眼
- 禁止使用 `alert / confirm / prompt / print`

## 六、命名约定

| 类别 | 规则 | 示例 |
|------|------|------|
| 文件名 | 小写 + 下划线 | `ch02_puzzle.js`, `chapter_manager.js` |
| 类名 | PascalCase | `Chapter02`, `ChapterManager` |
| 常量 | UPPER_SNAKE | `DESIGN_W`, `DESIGN_H`, `PASS_SCORE` |
| localStorage key | `ye_v1_` 前缀 | `ye_v1_progress`, `ye_v1_settings` |
| 用户可见文案 | 不用"游戏"字眼 | `"继续下一章节"` 而非 `"下一关"` |

---

## 七、开发期与上线打包

- 开发期用 ES Modules（`import/export`），浏览器通过本地服务器打开（ES Modules 不支持 `file://`）
- 上线用 `node build.js` → 输出 `build_out/index.html`（单文件，可直接打开或上传）
- `build.js` 做的三件事：按依赖顺序拼接所有 JS 文件 → 去掉 `import/export` 行 → 嵌入 `<script>` 标签
