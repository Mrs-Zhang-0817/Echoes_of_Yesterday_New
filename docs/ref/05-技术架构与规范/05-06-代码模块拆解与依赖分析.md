## 二、依赖关系图

```
main_new.js
  ├─ core/Game.js              (0依赖)
  ├─ core/InputManager.js      (0依赖)
  ├─ core/Loader.js            (0依赖)
  ├─ core/ProgressStore.js     (0依赖)
  ├─ core/ChapterManager.js    → 依赖 ArtworkMemoryReport ← ⚠ 反向依赖
  ├─ core/Overlay.js           → 依赖 ArtworkMemoryReport ← ⚠ 反向依赖
  ├─ data/assetManifest.js     (纯数据)
  ├─ data/chapters.json        (纯数据)
  ├─ chapters/ch01~ch10        (10章)
  │    ├─ utils/*              (工具函数)
  │    ├─ interactions/*       (交互模块)
  │    └─ narrative/*          (叙事模块)
  └─ ui/*                      (UI层)
```

**反向依赖问题：**
```
core/ChapterManager.js
  → import { REPORT_PROGRESS } from '../ui/ArtworkMemoryReport.js'

core/Overlay.js
  → import { showMemoryReport } from '../ui/ArtworkMemoryReport.js'
```

这意味着如果想把core剥离成独立模块，必须先解耦这个反向依赖。

## 四、模块间接口契约

### Chapter契约（5方法）
```js
class ChapterXX {
  constructor(game)     // 接收game对象，初始化状态
  onEnter()             // 进入章节：设置输入、加载资源、播放入场
  onExit()              // 离开章节：清理事件监听、释放资源
  update(dt)            // 每帧逻辑更新（毫秒增量）
  render(ctx)           // 每帧绘图（接收Canvas 2D上下文）
  get isComplete()      // 返回boolean，驱动下一章
}
```

### InputManager契约
```js
game.input.setHandlers({ down, move, up, cancel })
// down(point) — {x, y} 相对画布的归一化坐标(1280x720空间)
// move(point) — 同上
// up(point) — 同上
// cancel() — 输入取消
```

### Loader契约
```js
// 入口: new Loader(manifest).loadAll().then(onReady)
// 使用: game.images['manifestKey'] → Image对象 或 null(加载失败)
```

### ProgressStore契约
```js
ProgressStore.markChapterComplete(chapterId)  // 标记章节完成
ProgressStore.getCompletedChapters()           // 获取已完成章节数组
ProgressStore.getCurrentChapter()              // 获取当前应启动的章节
// 存储格式: localStorage ye_progress_v2 = JSON.stringify({completed: [...], ...})
```

## 五、重构建议

### P0 — 必须修
1. **ChapterManager反向依赖ArtworkMemoryReport**：当前直接用 import 引用UI层模块。改为事件回调机制——ChapterManager抛出 `'report-required'` 事件，由 main_new.js 监听后调用UI层。

2. **Overlay反向依赖ArtworkMemoryReport**：同上，改为事件驱动。

### P1 — 建议修
3. **ch05_door.js 916行**：无 `_renderSafe` 的 try/catch 包装（有但仅包了render调用），动画帧中可能抛出未捕获异常。添加完整错误边界。

4. **ch06_table.js 961行**：最大章节文件，`_updateGating1/_updateGating2` 可抽出为独立模块。

5. **ch08_sign.js 319行**：有独立的 rAF/DPR/事件系统（历史遗留），与全局InputManager/ChapterManager重复。重构进统一架构。

### P2 — 可缓修
6. 所有章节共享的 `getComicScene(chapterKey)` 和 `getChapterComics(sceneKey)` 接口已稳定，但文档不足。
7. 各章进度百分比硬编码 vs `chapters.json` 配置化 → 统一走配置。
