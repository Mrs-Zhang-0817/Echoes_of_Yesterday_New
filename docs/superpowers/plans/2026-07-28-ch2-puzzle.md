# Chapter 2 Puzzle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a zero-dependency, playable Canvas Chapter 2 flow from room to desk to a nine-piece fading-memory puzzle.

**Architecture:** A small scene manager owns scene lifecycle and black fade transitions. A normalized Pointer Events adapter sends logical coordinates to the active scene. The puzzle scene owns image slicing, the configurable B scattered layout, drag/drop, snap feedback, and its completion timeline.

**Tech Stack:** HTML5 Canvas 2D API, native ES Modules, Pointer Events, browser `requestAnimationFrame`.

## Global Constraints

- Use pure HTML5 Canvas and native ES Modules; add no dependency.
- Render at logical 1280×720 and preserve aspect ratio in the viewport.
- Target modern iOS 15+ and Android Chrome 90+ in landscape.
- Use `touch-action: none` and Pointer Events for touch and desktop input.
- Keep B layout values in `Scene_Puzzle.js` as `PUZZLE_LAYOUT`.
- Use the three supplied local assets and show a visible error state if loading fails.
- Do not implement the Chapter 2 key-finding segment.

---

## File Structure

- `index.html`: fullscreen Canvas host and module entry point.
- `src/main.js`: bootstrap, loader progress state, scene registration.
- `src/core/Game.js`: bounded-delta animation loop.
- `src/core/Loader.js`: image manifest loader with explicit failures.
- `src/core/InputManager.js`: viewport-to-logical Pointer Event mapping.
- `src/core/SceneManager.js`: scene lifecycle and 300ms transitions.
- `src/scenes/Scene_Room.js`: room hot zone and prompt.
- `src/scenes/Scene_Desk.js`: desk hot zone and prompt.
- `src/scenes/Scene_Puzzle.js`: configurable puzzle interaction.
- `tests/manual-smoke-checklist.md`: repeatable browser checks.

### Task 3: Configurable B-layout puzzle

**Files:**
- Create: `src/scenes/Scene_Puzzle.js`
- Modify: `src/main.js`

**Interfaces:**
- Consumes `game.images.puzzle`, `game.input` and canvas context.
- Exports `PUZZLE_LAYOUT` and `ScenePuzzle`.
- A piece has `{ id, sourceX, sourceY, targetX, targetY, x, y, width, height, placed, stackIndex }`.

- [ ] **Step 1: Implement constant-driven layout and deterministic piece creation**

Define `PUZZLE_LAYOUT` with panel position/size, `pieceScale`, `snapRadius: 50`, six visible `slots`, and three `stacks`. Slice the supplied image by passing each source rectangle to `drawImage`; do not create extra image files. Shuffle IDs with Fisher-Yates, assign six pieces to visible slots and three to stacks.

- [ ] **Step 2: Implement pointer drag and snapping**

On pointer down choose the topmost unplaced piece whose rectangle contains the point. On move update its position with stored pointer offset and move it to the end of the render-order array. On up compute `Math.hypot(piece.x - piece.targetX, piece.y - piece.targetY)`; values at most 50 snap and set `placed = true`, otherwise remain in place.

- [ ] **Step 3: Implement visual states and feedback**

Draw the target grid, grayscale loose pieces, reduced grayscale dragging piece with shadow, and full-color placed pieces. On a correct snap call `navigator.vibrate?.(15)` and create short-lived warm particles.

- [ ] **Step 4: Implement completed-memory timeline**

When all pieces are placed, progress through `completeHold` for 3 seconds and `fadeMemory` for 2 seconds. Render the complete image at full saturation then interpolate saturation from 1 to 0.3. Display the corresponding Chinese narrative text and log `Ch2 拼图完成` once.

- [ ] **Step 5: Confirm syntax and public configuration**

Run: `node --check src/scenes/Scene_Puzzle.js && rg -n 'PUZZLE_LAYOUT|snapRadius|slots|stacks' src/scenes/Scene_Puzzle.js`

Expected: syntax exits 0 and the configuration entries are present.
