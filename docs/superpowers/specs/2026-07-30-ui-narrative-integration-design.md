# UI 包与叙事补全设计规格

## 目标

将 `Echoes_of_Yesterday_UI_v1.1.zip` 中已验收的记忆恢复报告美术接入现有单 Canvas 游戏，并依据飞书《昨日重现 · 漫画剧情互动系统》补齐当前缺失的叙事与互动闭环；保持十章连续推进、单一输入层和本地进度可恢复。

## 不可违反的约束

- 运行本体继续是 `index.html` + 单一 `#gameCanvas`，不嵌入 ZIP 的 DOM 页面、CSS 页面系统或 `window.location.assign` 导航。
- 不修改根目录 `Echoes_of_Yesterday/` 旧仓库；只在当前 `Echoes_of_Yesterday_New` 工作区操作。
- UI 包的十张报告底图和三张透明按钮是导入资产，不属于新增生成图片。
- 新增生成图片的推荐预算为 **3 张**、硬上限为 **6 张**。每张必须承担不可由现有帧、裁切或动态效果替代的剧情转折；不为装饰或普通过渡生成整张场景图。
- 先复用现有图、ZIP 图、局部裁切、遮罩、显影/褪色、模糊、色调、文字、Canvas 几何和粒子；第二章五帧闪回属于可保留的“叙事帧”范例。不得为普通过渡新增整张场景图。
- 不添加第三方依赖；继续支持静态 HTTP 服务、横屏 1280×720 等比 Canvas、触摸和鼠标。
- 每章结束的报告必须由当前 `ChapterManager`、`Overlay`、`InputManager` 和 `ProgressStore` 统一驱动；不能出现双输入层或页面跳离游戏。
- 终章必须形成 100% 闭环，并在重新开始时保留现有清档回到 Ch1 的语义。

## 结算报告设计

### 共用数据

报告进度使用游戏实际累计值而非 ZIP 的旧配置：

`0 → 5 → 15 → 22 → 30 → 40 → 52 → 60 → 72 → 85 → 100`。

每个报告接收：`chapterNumber`、`memoryFrom`、`memoryTo`、`onContinue`。报告打开时锁定章节输入；底图先完整可见，再在 1.8 秒内从 `memoryFrom` 动画到 `memoryTo`。Ch3 的 `15 → 22` 与旧 UI 配置不同，以游戏实际进度为准。

### 画面与交互

- 每章使用对应完整底图，等比 cover 至 1280×720；不在底图已有排版区域重复绘制大段文字。
- 使用压缩包的“继续昨日”透明按钮作为唯一必需操作；点击区域略大于可见图，完成 120–150ms 的轻微下压后调用 `onContinue`。
- “返回主界面”“查看记忆档案”不在本期开放：当前游戏没有稳定的 Canvas 主菜单/档案状态，显示为不可点视觉或不绘制，避免伪入口。
- 进度动画包含低强度照片显影/暖色恢复与数字递增；不做奖励爆炸、强闪或现代 HUD。
- `prefers-reduced-motion` 时直接显示结束状态并立刻开放继续。

### Ch10

终章不使用普通结算卡。风铃结尾后依次展示：晨光客厅、粥的蒸汽、已有 Ch1–Ch9 关键图的裁切/显影蒙太奇、白场、最终第十章报告。写入 Ch10 完成和 100% 后再打开报告；“重新开始”沿用清存档后回 Ch1。

## 飞书叙事补全范围

本期不把每章改造成完整多媒体分镜，而是优先补齐“进入章节的动机 → 核心互动 → 可读的结果 → 下一章动机”的缺口。

### 新生成叙事帧预算

以下三张是推荐生成项；它们都承担当前资源无法清晰表达的情感转折。其余章节按现有资产和动态处理。

1. **Ch9 闪回：年轻的父亲亲手制作风铃。** 色块重构完成后短暂插入，说明风铃为何是父女共同记忆，再进入下落式音游。
2. **Ch10 近景：成年女儿端着粥、看向父亲。** 现有端粥人物图仅 250×250，无法承担“认出丫丫”的情绪特写。
3. **Ch10 高潮：父女在晨光里拥抱。** 用于“丫丫”被认出后的无操作高潮与最终报告前的停顿。

生成项若在浏览器实测中被现有高质量素材、局部构图与柔焦完整替代，可取消；任何第四张及之后的新增图必须先说明对应剧情节点、现有资产为何不足、以及为何不能以动态解决。

## 明确不在本期实现的外部能力

- 不接入真实摄像头识别、OCR、陀螺仪、光线传感器、豆包 API 或网络服务。
- Ch8 为后续摄像头实现留下受控占位和无摄像头回退，不能申请设备权限。
- 不新增音频引擎或未经提供的音乐/风铃音频；节奏反馈采用现有震动与视觉节拍，预留音频触发接口。

## 验收标准

1. Ch1–Ch9 每次完成都出现对应报告底图，点击继续能进入下一章且不跳离 Canvas。
2. 报告进度与 `ProgressStore` 一致；Ch10 报告为 100%。
3. Ch2/Ch3 闪回严格在前置拼图/路线高亮完全消失之后开始，速度柔和。
4. Ch4/Ch10 画面底部不露出错误棕色底板；Ch4 电话、手环为真实图像或可信裁切，不再用纯程序占位。
5. Ch6 香气粒子的吸附半径、阻尼和目标锁定显著稳定；Ch8 写出“向阳”可通过；Ch9 可完成两段互动并进入 Ch10。
6. 默认生成上述三张叙事帧，且总量不超过 6 张；每张都有对应剧情节点和验收截图。若 Ch4 裁切被视觉审查否决，可在上限内追加电话/手环物件图并记录原因。
7. `npm test`、相关视觉/浏览器流程和 `git diff --check` 通过；Git remote 确认为 `Echoes_of_Yesterday_New.git` 后再提交。根据项目规则，GitHub 推送由用户本机终端执行。
