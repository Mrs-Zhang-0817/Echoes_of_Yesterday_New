# 《昨日重现》Ch2 拼图关卡设计

## 目标

在横屏移动端完成可试玩的 Chapter 2 第一段：从客厅进入桌面，完成 3×3 父女照片拼图，短暂恢复彩色后再次褪色。找钥匙玩法不在本次范围内。

## 场景流

1. `room`：渲染客厅背景。点击桌面区域进入 `desk`；点错时提示文本短暂强调。
2. `desk`：渲染桌面特写。点击散落照片区域进入 `puzzle`；点错时提示文本短暂强调。
3. `puzzle`：渲染 9 块灰度照片碎片、目标网格和提示文字。玩家拖动碎片至正确格位，松手且距离不超过吸附半径时归位并恢复彩色。
4. 全部归位后，完整照片保持彩色 3 秒，再用 2 秒降低饱和度；显示最终文案并在控制台记录完成事件。

场景切换统一使用 300ms 黑色淡入淡出。

## B 布局：环绕散落

中央为 3×3 目标网格。六块碎片位于网格外围的固定可见槽位；另三块放在三个边缘叠放组中。每个叠放组只显示最上层，但其余块保持独立位置和 z-index；拖走最上层后，下一块自动露出。这样保留“桌面散落”的视觉，同时确保 16:9 小屏不因九块大碎片相互遮挡而无法操作。

所有易变数值集中在 `Scene_Puzzle` 的 `PUZZLE_LAYOUT`：面板宽高、碎片缩放、外围槽位、叠放偏移、吸附半径和安全边距。修改布局不会触碰切图、命中、拖拽、吸附或完成判定。

## 技术边界

- 纯 HTML5 Canvas 与原生 ES Modules；不新增依赖。
- 逻辑画布为 1280×720，等比适配全屏。
- 使用 Pointer Events 统一鼠标与触摸，使用 `touch-action: none` 防止页面滚动和缩放干扰。
- `navigator.vibrate(15)` 仅在支持时调用；不支持时仍提供画布粒子反馈。
- 资源加载失败会显示明确错误页，不静默进入空白场景。

## 模块职责

- `main.js`：创建全局 `game`，加载资源，注册并启动场景。
- `core/Game.js`：基于 `requestAnimationFrame` 的更新和渲染循环。
- `core/Loader.js`：并行预加载图片，暴露加载进度与失败原因。
- `core/InputManager.js`：将浏览器输入转换为逻辑坐标，并向当前场景分发事件。
- `core/SceneManager.js`：场景实例生命周期和淡入淡出。
- `scenes/Scene_Room.js`、`Scene_Desk.js`：背景、热区和提示。
- `scenes/Scene_Puzzle.js`：切片、B 布局、拖拽、吸附、粒子与完成状态机。

## 验收

- 现代桌面浏览器和横屏移动端可加载三张本地素材，无控制台错误。
- 客厅和桌面只能通过对应画面热区进入下一场景；错误点击给出提示。
- 拼图界面初始可见六块碎片及三个叠放组；所有九块均可拖拽。
- 错误位置松手后碎片停留在释放位置；正确位置 50px 内松手后吸附、变彩色并产生反馈。
- 九块归位后按 3 秒彩色、2 秒褪色的顺序完整演出。
