# Ch4 签字迁移、Ch7 弹幕与 Ch8 镜中微笑设计

## 目标

将已有的签字还原玩法从第八关迁回警局第 4 关；在第 7 关加入可点击的安抚弹幕气泡；第 8 关改为前置摄像头微笑识别，并提供不依赖摄像头的挥手回退。三项功能全部留在现有单 Canvas 游戏流程中。

## 范围与边界

- 不改动 WorkBuddy 正在整理的 `src/narrative/`、报告资产、`ChapterManager`、`Overlay` 及其测试。
- 只修改 Ch4、Ch7、Ch8、关卡元数据、入口资源注册，并新增与互动直接相关的模块、模型和回归测试。
- 引入用户提供的 `face-api.min.js` 与其 TinyFaceDetector、表情识别模型；不使用压缩包内的 HTTPS 服务器和证书文件。
- 摄像头视频只在浏览器本机内存中供检测和 Canvas 预览使用；不上传、不存储。用户主动点击“开启摄像头”才申请权限，离开/完成后停止所有媒体轨道。

## 方案取舍

推荐将三个玩法做成独立的 Canvas 互动单元后嵌入章节状态机：

1. Ch4 保留电话和手环线索，二者之间插入复用的签字还原单元。
2. Ch7 以可点击气泡替代仅飘过的纯弹幕，点击后气泡变成暖色微光并削弱恐惧遮罩；完成收集后再进入现有找门锁流程。
3. Ch8 采用本地 face-api.js 判定 `happy >= 0.6` 持续 1.5 秒；摄像头不可用、模型失败或用户拒绝授权时，提供一次向上弧形挥手完成的同等通关路径。

不采用“保留 Ch8 签字并附加微笑”的方案，因为会重复两个核心玩法、破坏飞书策划的章节叙事；不采用纯 DOM 页面，因为会绕开当前统一 Canvas 输入、转场和存档。

## 章节流程

### Ch4 警局

`电话 → 来电演出 → 签字还原 → 手环揭示 → 结算`

签字保留原有笔画畸变、清除、提交、提示和可完成性规则；完成时不自行写入第 8 关存档，而是把控制权交回 Ch4。Ch4 完成后写入第 4 关进度与当前统一报告进度。

### Ch7 暗夜的微光

`开场 → 安抚气泡 → 找门锁 → 开门 → 结算`

气泡沿现有 1280×720 Canvas 右侧进入，最多 5 个并发。点击命中后不再参与弹幕移动，而是以 0.45 秒飞向胸口位置的微光粒子呈现。收集 4 个即开始现有找门锁阶段；20 秒内未收集足够时自动补足，避免卡关。原门锁的 60 秒兜底保留。

### Ch8 走廊的镜子

`镜中陌生人 → 用户选择/启动摄像头 → 微笑判定或挥手回退 → 裂纹消退、陌生人变为微笑 → 结算`

- 模型预加载失败或不支持 `getUserMedia`：直接显示挥手引导。
- 相机权限被拒绝、设备不可用、视频 8 秒未就绪：切换到挥手引导，不重复弹权限请求。
- 摄像头路径每 200ms 检测一次，只接受单张脸的 happy 分数；连续 1.5 秒达到 0.6 才完成。
- 挥手路径要求触点从左向右且横向距离不少于 35% 画布宽度，纵向波动存在，以避免普通点击误过关。

## 文件与资源

- 新增 `src/interactions/DanmakuBubbleField.js`：基于现有弹幕包思想，负责生成、命中、飞向胸口和绘制，不依赖 DOM。
- 新增 `src/interactions/SignaturePuzzle.js`：从 Ch8 分离出签字数据、输入和渲染，可通过完成回调复用到 Ch4。
- 新增 `src/interactions/SmileDetector.js`：封装模型加载、视频生命周期和表情采样；不负责章节 UI。
- 替换 `src/chapters/ch08_sign.js` 的章节实现为镜中微笑流程，文件名保留以避免注册和外部链接同时变化。
- 将提供的 face-api 脚本和模型放入 `assets/vendor/face-api/`，在 `index.html` 的模块入口前加载脚本；不导入其中的证书或服务器文件。

## 验收与测试

1. Ch4 从电话进入签字，还原成功后再显示手环，最终只写入 Ch4 完成状态。
2. Ch7 至少四个气泡可点击、命中后有微光反馈，20 秒兜底能进入门锁阶段，原门锁流程仍可完成。
3. Ch8 在浏览器许可摄像头时显示镜像预览，达到阈值后完成；拒绝权限或 HTTP 静态服务器环境可用挥手完成；离开章节后摄像头轨道已停止。
4. Node 测试覆盖三个互动模块的状态/回退规则；Playwright 覆盖 Ch4、Ch7、Ch8 的核心流程，并检查无未处理页面错误。
5. `npm test`、相关 Playwright 测试及 `git diff --check` 通过；不暂存或提交 WorkBuddy 的任何文件。

## 风险与约束

- 真正的人脸识别依赖安全上下文（HTTPS 或 localhost）和用户授权；这是浏览器限制，挥手回退保证游戏不因此不可玩。
- 提供的 face-api 包未包含许可证说明；在公开发布前应补充其上游许可证与归属核验。
- 现有运行时将 Ch8 注册为 `ch08`，但其源文件名是 `ch08_sign.js`；本期保持文件名不动，减少与 WorkBuddy 整理的重命名冲突。
