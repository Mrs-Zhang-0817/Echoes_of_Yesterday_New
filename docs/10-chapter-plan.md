## 二、10 关设计（含线索 / 容错 / 记忆数值）

### 核心策略

每关统一结构：`背景画面 + 文案叙述 + 1个核心互动 + 过渡`。
**铁律：凡需要"知识"的关卡，线索必须在前置关卡给出；凡可能失败的关卡，3 次失败必给自动辅助。**

### 敏捷策略：先串联骨架，后填充关卡（Walking Skeleton）

**现在就串联，不等关卡开发完。** 串联的不是关卡逻辑，而是框架：
- **Phase 1 就建好 ChapterManager + 10 个占位章节**，当晚 17:00 起任何时刻都有一个"10 章全线可导航"的完整产品——这本身就是第一个可上线、可给玩家试玩的版本。
- 之后每个关卡独立开发，完成一个就"点亮"一个（用自己的 `chapters/chNN.js` 替换占位），**不碰框架、不碰其他关卡**。
- 为什么不"独立开发完再统一串联"：那是大爆炸集成——10 个关卡的输入冲突、生命周期、坐标/DPR 差异会在最后 1 小时集中爆发，没时间修。骨架期定好统一接口（onEnter/onExit/update/render/complete），后面填关卡就是填空。
- 玩家测试的价值在完整叙事流：评委体验的是 Ch1→Ch10 情感弧线，断成 10 个孤立 demo 无法传达主题。

## 三、产物结构与技术决策（v2 修正）

### 产物形态（修正 R1）

```
zip 根目录：
├── index.html          # 唯一入口；JS/CSS 全部内联为单个 <script>（原因：妙搭托管实测不支持 ES Modules，非抖音要求）
└── assets/images/      # 相对路径引用的压缩图片（平台规则明确允许）
    ├── scene_room.jpg / scene_desk.jpg / scene_puzzle.jpg
    ├── sign_scene.jpg（由 png 压缩转 jpeg）
    └── ch1_bg.jpg（主界面底图压缩版）
```

- 禁止：`__MACOSX`、`.DS_Store` 进 zip；zip 内多包一层目录。
- 打包命令：`cd build_out && zip -r ../ye.zip . -x "*.DS_Store"`。

### 技术决策（修正后）

1. **JS/CSS 全内联单 `<script>`**：为兼容妙搭与旧 WebView（已实证），图片走 zip 内相对路径。
2. **开发态模块化**：`chapters/ch01.js … ch10.js` + `core/`（ChapterManager/AssetLoader/GameLoop/InputManager/Overlay/ProgressStore），`build.js`（Node，无依赖，读文件按序拼接）→ 输出 `build_out/index.html`。**4 人并行各改各的章节文件，零冲突。**
3. **骨架先行**：P1 注册全部 10 章，未实现的关为"占位章节"——程序化背景 + 本章完整文案演出 + 长按 1s 继续。任何时刻产品都完整可玩，之后逐关点亮（替代 v1"记忆碎片浮现中…"）。
4. **进度 localStorage**：key `ye_progress_v1`，存 `{ chapter, memory, completed:[], ts }`。
5. **无音效**（省体积+autoplay 限制），震动反馈 `navigator.vibrate` 可选调用（iOS 不支持时静默跳过）。
6. **横屏 fixed 1280×720**，竖屏全屏遮罩提示旋转（复用 Ch2 已验证实现）；DPR：backing store 固定 `1280×720×DPR`，CSS 独立等比缩放（fix-log 实证方案）。
7. **ctx.filter 兜底**：拼图褪色/灰度用**离屏 Canvas 预生成**灰度版本，不依赖运行时 `ctx.filter`（iOS Safari <18 不支持）。
8. **文案红线**：面向用户文本禁用"游戏/通关/玩家/输赢"，统一"章节/片段/继续/体验"；结算弹层必须有结果+下一步按钮，且同时只有一个激活主弹层。
9. **错误兜底**：`window.addEventListener('load')` try/catch + 自绘错误弹层；图片加载失败→重试 1 次→ErrorModal。
