## 0. 一句话概览

一款 **1280×720 横屏 Canvas 2D** 叙事互动游戏，以**阿尔茨海默症父亲的第一人称视角**展开，共 **10 章**。玩家通过点击 / 拖拽 / 手写等轻交互，逐章"唤醒"记忆。全局有一条"记忆恢复进度"主线，章节过关写入 `ProgressStore`（localStorage key `ye_v1_progress`），终章以"记忆恢复档案"报告页收尾，可一键重新开始。

## 1. 技术架构总览

### 1.1 运行形态
- **开发态**：`src/` 下 ES Modules 模块化（每章一个 `class`，核心框架在 `src/core/`）。
- **上线态**：`build.cjs` 将模块拼接为单文件 `index.html`，用于抖音互动空间投放。
- 入口 `index.html` 直接 `<script type="module" src="src/main_new.js">`，无 `dist/` 依赖（已被 gitignore）。

### 1.2 主循环与帧率
- `Game.js` 用 `requestAnimationFrame` 驱动；每帧 `dt = min((timestamp - lastTime)/1000, 0.1)`——**单帧时间上限 100ms**（切后台/卡顿时不让 dt 爆掉）。
- 渲染顺序：`章节 render` → `转场 renderTransition` → `全局 Overlay`。

### 1.3 章节状态机与转场
- `ChapterManager.js` 持有当前章节实例，驱动 `onEnter / update / render / handleDown…` 生命周期。
- **转场参数**：`transition = { phase:'idle', alpha:0, duration:0.3 }`——即**章节与章节之间是一段 300ms 的黑屏淡入淡出**（`renderTransition` 用 `rgba(0,0,0,alpha)` 铺满）。
- 当 `chapter.isComplete` 为真时：弹**完成 Overlay**（`type:'complete'`，单按钮"继续下一章节" → `next()`），并把 `phase` 置 `'blocked'` 阻断交互直到用户点击。

### 1.4 全局叙事弹层 Overlay
- 遮罩 `rgba(0,0,0,0.6)`；卡片 **420×280** 居中（圆角 16）。
- 标题 `#2a1a0c` bold 24px；正文 `#4d3420` 17px；按钮 180×44（`#4d3420` 底 / `#fcf5e6` 字）。
- **排他性**：`if (this.active) return;` —— 同一时刻只允许一个弹层。
- 复用 `src/ui/ArchiveUI.js` 的 `drawArchivePanel / drawArchiveStamp / drawArchiveButton`。

### 1.5 进度存储
- `ProgressStore.js`：localStorage key **`ye_v1_progress`**。
- `markChapterComplete(num, memory)`：取 `max(旧值, memory)` 写入（累计、不回退）。
- `reset()`：清档。
- 进度恢复：`resumeNum = min(saved.chapter + 1, 10)`——完成第 N 章后重进从 N+1 章开始。

### 1.6 输入系统
- `InputManager.js`：指针事件（pointerdown/move/up/cancel）+ `setPointerCapture`；坐标经 `getBoundingClientRect` + `scaleX/Y` 换算到 1280×720 设计坐标；阻止 `contextmenu` / 手势缩放。

### 1.7 资源加载与降级
- `Loader.js`：`loadImages(manifest, onProgress)`，单图失败→`createPlaceholder`（**256×256 斜纹 + "missing asset"**），**永不 reject**——任一图缺失都不会让游戏崩，只是显示占位图。
- 加载页文案：**"正在唤醒记忆……{loaded}/{total}"**。

### 1.8 调试接口（main_new.js）
- `D`：快照；`F`：强制完成当前章；`1`–`0`：跳转到对应章（仅开发期）。

### 1.9 竖屏提示
- `createRotateHint()`：窄屏（竖屏）时显示"请旋转设备"遮罩，保证横屏体验。

## 3. 逐章详述（Ch1–Ch10）

> 每章给出：叙事定位 → phase 状态机 → **动效与时长表** → 视觉/美术 → 屏上提示文案 → 过关记忆值 → 已知问题。

### 3.1 Ch1 序曲·镜前（`ch01_intro.js`）
- **叙事**：父亲站在镜前，凝视镜中自己，点击触发镜面碎裂，引出"记忆的碎片"。
- **phase**：`idle → shattering → complete`
- **镜面**：椭圆 `MIRROR_CX=640, CY=340, RX=250, RY=325`；呼吸光 alpha `0.05 + sin(breathTime*2π/3)*0.05 + 0.05`（**周期 3s**）。
- **触发**：点击镜热区椭圆 **或** 累计点击 **3 次** → `startShattering`。
- **碎裂动效**：**30 个碎片粒子**（初速 80–300，存活 1.5–2.5s，铜→白渐变）+ **5–7 条裂纹**；`vibrate(30)`。
- **节奏**：碎裂后 **0.3s** 裂纹渐显（再 **0.5s** 淡入）；**2s 后** `complete` → `markChapterComplete(1, 5)`。
- **完成弹层**：标题"回忆的碎片" / 正文"镜中的自己……是谁？"
- **美术**：仅 `mainMenuBg` + 程序化压暗 `rgba(13,8,5,0.55)`；卧室/镜子/收音机套件**全未用**。
- **屏上提示**："凝视镜中的自己……"

### 3.2 Ch2 接女儿放学（`ch02_puzzle.js`）
- **叙事**：3×3 拼图复原"接女儿放学"的场景记忆。
- **phase**：`playing → completeHold → fadeMemory → complete`

- **节奏**：拼合完成 → `completeHold` **3s** → `fadeMemory` **2s** → `markChapterComplete(2, 15)`。
- **闪回帧**：`ch2_flashback_0{1-5}`，`frame = min(5, floor(phaseTime*1.7)+1)`（fadeMemory 阶段循环播放）。
- **完成弹层**：标题"记忆恢复了一些……" / 正文"但那抹色彩，终究会慢慢褪去……"

- **屏上提示**：AI 提示"您的家在有向日葵贴纸的那一层。"

### Ch2：拼图完成后的记忆闪回顺序错误

- **当前问题**：九块拼图完成后，`completeHold` 阶段已开始以 32% 透明度叠加闪回；拼图尚在画面上、高亮和视觉注意力没有完全收束，闪回已出现。随后 `fadeMemory` 一开始又快速提高闪回不透明度，造成“拼图还没离场，记忆已抢先闪出”的叠层感。

4. 排列正确后，符号散开并转化为彩色乐谱线，作为进入下一互动的视觉奖励。

#### 互动 B：音叉风铃（音游核心）

1. 镜头对准一排带 2.5D 金属质感的风铃管，每根贴对应颜色贴纸；风铃位置和判定线必须一眼可见。
2. 彩色音符从屏幕上方下落，到达判定线时点击对应颜色风铃管。
3. 正确命中产生 Combo；单音风铃声逐步融入完整音乐织体。
4. 随 Combo/进度推进，整个客厅从清冷转为金色暖光。
5. 最后一个音符触发完整旋律，主角落泪，作为 Ch9→Ch10 的情绪桥。

#### Ch9 的实施前提

- 需要重新建立风铃管、颜色贴纸、下落音符、判定线、Combo、暖光和结局人物反馈的资源/状态机。
- “单音—织体—完整旋律”要求新增真实音频系统；当前项目没有任何音频能力。
- 必须先定义命中窗口、漏击处理、连击中断、移动端点击热区与无声音降级，避免重新造成 Ch9→Ch10 卡关。

### Ch9 → Ch10：当前存在卡关，先复现再修复

- **现象**：当前从 Ch9 进入 Ch10 存在卡关，用户已明确报告；在根因未复现前，不能将其归咎为单一资源或动画问题。
- **最低复现路径**：新存档 → 完成 Ch1–Ch8（可用现有开发跳章辅助缩短）→ Ch9 五个音符全归位 → 点击统一完成弹层“继续下一章节” → 观察是否黑屏、停留在 Ch9、Overlay 持续存在、输入失效或 Ch10 渲染异常。
- **修复验收**：Ch9 结算按钮可进入 Ch10；Ch10 背景在 1280×720 与手机横屏下不露棕色底板；点击热粥能进入报告页；浏览器无 `error`/`pageerror`。

### Ch10：背景定位与底板露出

- **问题**：终章背景图片的定位/覆盖不准确，露出棕色底板；与 Ch4 的背景缺口属于同类可见问题，但需分别定位各自的绘制顺序和裁切。
- **目标**：背景、桌面、热粥与报告过渡形成有意的层次；任何棕色区域必须是明确的木桌或场景内容，不能是 Canvas 裸底或错误补板。
- **验收**：桌面横屏、常见手机横屏、白场淡出起点和报告页四个状态均截图检查。

## 6. 给"倒推修改"的中性观察

> 以下仅描述"现状特征"，不替你下结论；改哪、怎么改，留给文档层面的讨论。

## 7. 当前主线的玩家旅程（按实际可达顺序）

本节不复述每个类的代码，而是把玩家从打开页面到重开的实际路径压成一条连续体验线，供后续直接逐句修改。

1. **加载与进入**：深棕加载页显示“昨日重现 / 正在准备记忆碎片…”。加载完成后，没有菜单或角色说明，直接进入镜前。
2. **镜前自我陌生化**：玩家读到“凝视镜中的自己……”，点击镜面；镜裂、碎片飞散，随后由统一档案卡告诉玩家“镜中的自己……是谁？”。
3. **学校照片复原**：不经过家庭或女儿出场的铺垫，玩家直接拼九块照片；完成后的五帧闪回补充父女在学校门口的视觉记忆。
4. **去希望小学**：地图出现，玩家画出一条连续路线；失败会被短暂红闪后清空，成功即叠放城市上推图，并说“要赶紧去接她”。
5. **警局线索**：旧城工地背景上出现自绘电话；接听后看见“XX小区 5栋 503”，再点手环。此处看似给出了明确归家信息。
6. **实际归家机制**：黑底旁白说父亲坐女儿的车回老小区，随后直接面对电梯。玩家不输入 503，而是根据 AI 管家文字选带向日葵的“6”。正确后电梯上升，进入家庭厨房。
7. **食物从恐惧到熟悉**：玩家先把手停在碗上使“安全感”满格，再把三类漂浮香气吸到目标位。此过程是当前主线中互动层次最多的一段；成功时抽象食物变暖、文字说“这味道……好熟悉”。
8. **黑暗找门锁**：夜卧室中靠局部光寻找门锁；长时间找不到会被月光和“任意点开门”的兜底带过。门开后进入签字确认。
9. **笔迹确认身份**：镜中笑脸和走失老人登记单推近为纯纸张。玩家没有描红目标，只能自由书写并接受笔迹畸变与分类判定；成功后系统确认“李向阳”。
10. **风铃归位**：在阳台将五个音符拖到风铃上，风铃短暂摆动。没有真实铃声，主要是视觉上的轻量缓冲章。
11. **热粥与档案**：晨光客厅中点击热粥，白场后显示十章档案。即使前九章都完成，档案仍显示 85%、第十章未完成；玩家只能点“重新开始”清档回到镜前。

这条旅程说明：当前版本已经具备“可从 Ch1 走到 Ch10”的完整可达链，但线索因果、声音承诺、视觉主体一致性和终局完成感尚未形成闭环。这些是后续先改文档、再倒推呈现时最值得逐项决策的对象。
